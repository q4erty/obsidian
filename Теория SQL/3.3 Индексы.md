**Индекс** — это структура данных, которая помогает быстро находить строки в таблице по одному или нескольким столбцам. По сути, индекс похож на оглавление книги: чтобы найти нужную главу, вы сначала смотрите в оглавлении, где указаны номера страниц, а затем сразу переходите к нужной странице, минуя чтение всего текста подряд.

Давайте представим что оглавления в книге нет, соответственно нам необходимо пролистать каждую страницу, чтобы найти, то что ищем. Так же делает и СУБД при отсуствии индекса - сканирует всю таблицу.

_1. B-Tree Index (индекс B-дерева)_ 

_Самый распространенный тип индекса**.**_ Он организует данные в виде сбалансированного дерева, что позволяет быстро находить нужные значения. Подходит для большинства случаев, когда требуется быстрый поиск по диапазону значений или точному значению.

_2. Hash Index (хэш-индекс)_  

Хэш-индексы используют хеш-функцию для преобразования значений ключей в адреса памяти. Они эффективны для точного совпадения, но не подходят для поиска по диапазонам или сортировки.

_3. Bitmap Index (битовый индекс)_  

Битовые индексы хорошо работают с малыми наборами уникальных значений (например, пол, статус заказа). Они занимают меньше места и быстрее работают в случаях, когда нужно искать по множеству значений одновременно.

_4. Full Text Index (полноэкранный индекс)_  

Полноэкранные индексы предназначены для поиска по текстовым данным. Они позволяют выполнять сложные текстовые поиски, такие как поиск по ключевым словам или фразам.

_**Когда стоит создавать индексы?**_

Индексы полезны в следующих ситуациях:

- Частые выборки по конкретным столбцам. Если вы часто выполняете запросы, фильтрующие данные по определенному столбцу, создание индекса на этом столбце может значительно ускорить выполнение таких запросов.

- Соединения (JOINs). Индексы на столбцах, участвующих в соединениях, могут ускорить выполнение запросов с использованием JOIN.

- Уникальные идентификаторы. Столбцы, содержащие уникальные идентификаторы (например, первичные ключи), обычно индексируются автоматически.

_**Недостатки индексов**_

Хотя индексы улучшают производительность чтения данных, они имеют некоторые недостатки:

- Замедление операций записи. Каждый раз, когда вы добавляете, обновляете или удаляете строку, индекс также должен быть обновлен, что может замедлить эти операции.

- Дополнительное пространство. Индексы занимают дополнительное место на диске, что может стать проблемой для очень больших таблиц.
