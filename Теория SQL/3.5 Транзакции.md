_**Принципы ACID**_

Транзакции — это фундаментальный механизм обеспечения целостности данных в системах управления базами данных (СУБД). Они позволяют группе операций выполняться как единое целое, гарантируя, что либо все операции успешно завершатся, либо ни одна из них не повлияет на состояние базы данных. Этот принцип называется ACID (Atomicity, Consistency, Isolation, Durability).

Самый распространенный пример транзакции - перевод денег с одного банковского счета на другой.

1. Атомарность (Atomicity): Все операции в транзакции должны быть выполнены целиком или не выполнено вообще. Если какая-то операция завершается неудачно, вся транзакция откатывается назад.

2. Согласованность (Consistency): После успешного завершения транзакции база данных остается в согласованном состоянии. То есть, все правила и ограничения базы данных соблюдаются.

3. Изолированность (Isolation): Параллельные транзакции не должны влиять друг на друга. Каждая транзакция работает так, будто она единственная, выполняемая системой.

4. Долговечность (Durability): Результаты успешной транзакции сохраняются даже в случае сбоя системы. Данные остаются неизменными после фиксации транзакции.

_**Управление транзакциями**_

В SQL для управления транзакциями используются следующие команды:

1. BEGIN TRANSACTION / START TRANSACTION: Начинает новую транзакцию.

2. COMMIT: Фиксирует изменения, сделанные в ходе транзакции, делая их постоянными.

3. ROLLBACK: Откатывает все изменения, сделанные в ходе транзакции, восстанавливая исходное состояние базы данных.

4. SAVEPOINT: Устанавливает точку сохранения внутри транзакции, до которой можно вернуться при необходимости.

```sql
BEGIN TRANSACTION;

UPDATE accounts SET balance = balance + 500 WHERE account_id = 123;
UPDATE accounts SET balance = balance - 500 WHERE account_id = 456;

COMMIT;
```

В данном примере две операции выполняются в рамках одной транзакции. Если обе операции успешны, изменения фиксируются командой COMMIT. Если хотя бы одна из операций завершается неудачно, вся транзакция откатывается командой ROLLBACK.

_**Уровни изолированности**_

Уровень изоляции определяет, насколько изолированы параллельные транзакции друг от друга. Существуют четыре уровня изоляции:

1. Read Uncommitted (Чтение неподтвержденных данных): Самая низкая степень изоляции. Позволяет читать данные, которые еще не были зафиксированы другими транзакциями. Может привести к "грязному чтению".

2. Read Committed (Чтение подтвержденных данных): Чтение данных, которые были подтверждены другими транзакциями. Исключает "грязное чтение", но допускает "неповторяемое чтение".

3. Repeatable Read (Повторяемое чтение): Гарантирует, что данные, прочитанные в начале транзакции, останутся неизменными до конца транзакции. Исключает "грязное чтение" и "неповторяемое чтение", но допускает "фантомные чтения".

4. Serializable (Последовательное исполнение): Наивысший уровень изоляции. Гарантирует, что результаты параллельных транзакций будут такими же, как если бы они выполнялись последовательно. Исключает все виды аномалий, но может снижать производительность.
