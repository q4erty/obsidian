## 1. Введение: Зачем понадобился новый клиент?

До появления Java 11 разработчики использовали класс `HttpURLConnection` (который был написан еще в эпоху Java 1.1 и был очень неудобным) или подключали сторонние громоздкие библиотеки (Apache HttpClient, OkHttp).

Начиная с Java 11, в стандартную библиотеку (пакет `java.net.http`) был добавлен новый, мощный и удобный API для работы с сетью. Он поддерживает протоколы HTTP/1.1, HTTP/2 и WebSockets.

**Четыре главных класса нового API:**

1. **`HttpClient`**: Сам клиент (аналог браузера). Отвечает за настройки соединения (версия HTTP, прокси, таймауты).
    
2. **`HttpRequest`**: Описание того, _что_ мы хотим отправить (адрес, метод, заголовки, тело).
    
3. **`HttpResponse`**: То, _что_ мы получаем в ответ от сервера (статус-код, заголовки, тело ответа).
    
4. **`WebSocket`**: Класс для работы с двунаправленными постоянными соединениями (веб-сокеты).

## 2. Создание клиента (`HttpClient`)

Клиент создается один раз и может использоваться для отправки множества запросов. Создать его можно через фабричный метод или паттерн Builder.

**Простое создание:**

Java

```
HttpClient client = HttpClient.newHttpClient(); 
// Создает клиента с настройками по умолчанию
```

**Продвинутое создание (через Builder):**

Java

```
HttpClient client = HttpClient.newBuilder()
    .version(HttpClient.Version.HTTP_2) // Принудительно используем HTTP/2
    .connectTimeout(Duration.ofSeconds(10)) // Ждем подключения максимум 10 секунд
    .followRedirects(HttpClient.Redirect.ALWAYS) // Автоматически переходить по 3xx редиректам
    .build();
```

## 3. Формирование запроса (`HttpRequest`)

Запрос также конструируется с помощью паттерна Builder. Запросы в Java **иммутабельны** (неизменяемы).

**Пример GET-запроса:**

Java

```
HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://api.github.com/users")) // Куда стучимся
    .header("Accept", "application/json") // Добавляем заголовок
    .GET() // Указываем метод (по умолчанию и так GET)
    .build();
```

## 4. Добавление тела в запрос (Body)

Если мы используем методы `POST` или `PUT` (например, отправляем данные формы или JSON), нам нужно добавить тело запроса (Body). Для этого используется специальный класс-помощник **`HttpRequest.BodyPublishers`** (Публикатор тела).

**Как добавить тело:**

Методы `POST()` и `PUT()` принимают объект `BodyPublisher`.

- `BodyPublishers.ofString("{\"name\": \"John\"}")` — отправить обычную строку (чаще всего JSON).
    
- `BodyPublishers.ofFile(Paths.get("data.txt"))` — прочитать файл с диска и отправить его.
    
- `BodyPublishers.ofByteArray(bytes)` — отправить массив байтов.
    
- `BodyPublishers.noBody()` — если тело не нужно (для пустого POST-запроса).
    

**Пример POST-запроса:**

Java

```
HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://my-api.com/users"))
    .header("Content-Type", "application/json")
    .POST(HttpRequest.BodyPublishers.ofString("{\"login\": \"admin\"}")) // Добавили Body
    .build();
```

## 5. Выполнение запросов (Синхронно и Асинхронно)

Когда клиент и запрос готовы, мы просим клиента выполнить запрос. В этот момент нужно указать **`BodyHandler`** — инструкцию для Java, как ей преобразовать полученные от сервера байты (тело ответа) во что-то понятное. Чаще всего используют `HttpResponse.BodyHandlers.ofString()` (сделать из ответа строку).

### А. Синхронные запросы (`send`)

- Метод: `client.send(request, handler)`
    
- **Как работает:** Поток, в котором вызван метод, блокируется и ждет, пока сервер не пришлет ответ.
    
- _Использование:_ Простые скрипты, или когда следующий шаг программы строго зависит от ответа.
    

### Б. Асинхронные запросы (`sendAsync`)

- Метод: `client.sendAsync(request, handler)`
    
- **Как работает:** Метод моментально возвращает объект `CompletableFuture<HttpResponse<T>>`. Текущий поток не блокируется и идет выполнять код дальше. Запрос выполняется «в фоне» (в другом потоке пула).
    
- _Зачем нужно (дополнение):_
    
    1. Если нужно отправить сразу 10 запросов параллельно, а не ждать каждый по очереди.
        
    2. Если ответ от сервера не критичен прямо сейчас (например, мы просто отправили лог или статистику "Fire-and-forget").
        

**Пример асинхронного вызова:**

Java

```
client.sendAsync(request, HttpResponse.BodyHandlers.ofString())
      .thenApply(HttpResponse::body) // Когда ответ придет, берем только его тело
      .thenAccept(System.out::println); // И выводим в консоль
// Основной поток пойдет дальше, не дожидаясь System.out.println
```

## 6. Работа с куками (Cookies)

HTTP не имеет «памяти». Если вы авторизовались на сайте, сервер присылает вам сессионную Cookie. Чтобы при следующем запросе сервер вас узнал, вы должны прикрепить эту Cookie к запросу.

- **Вручную:** Можно парсить заголовки `Set-Cookie` из ответа и добавлять заголовок `Cookie` в следующий `HttpRequest`. Это долго и неудобно.
    
- **Автоматически (CookieManager):** В Java есть удобный класс `CookieManager`, который может делать всё сам.
    

**Как настроить автоматическую работу с куками:**

Java

```
// 1. Создаем менеджер куки (он будет хранить их в памяти)
CookieManager cookieManager = new CookieManager();

// 2. Привязываем его к нашему HttpClient при создании
HttpClient client = HttpClient.newBuilder()
    .cookieHandler(cookieManager) 
    .build();

// Теперь, если сервер пришлет куки, client автоматически их сохранит 
// в cookieManager. А при следующем запросе к этому же серверу — 
// автоматически подставит нужные куки в заголовки!
```
