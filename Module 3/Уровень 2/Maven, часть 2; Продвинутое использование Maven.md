## 1. Продвинутая сборка и Плагины

Как мы помним, сам Maven — это лишь "скелет". Всю реальную работу по компиляции, копированию и упаковке делают **плагины**. Для гибкой настройки процесса сборки разработчики используют специальные плагины, прописывая их в блоке `<build><plugins>` файла `pom.xml`.

**Самые популярные плагины для настройки сборки:**

1. **`maven-compiler-plugin`**: Управляет компиляцией Java-кода.
    
    - _Дополнение:_ По умолчанию Maven может использовать старую версию Java (например, 1.5). Именно через этот плагин мы жестко задаем, что хотим использовать, например, Java 11 или 17 (настраивая параметры `source` и `target`).
        
2. **`maven-resources-plugin`**: Управляет файлами ресурсов.
    
    - Отвечает за то, чтобы скопировать ваши `.properties`, `.xml`, картинки и шаблоны из `src/main/resources` в итоговую папку `target/classes`.
        
3. **`maven-source-plugin`**: Собирает исходный код.
    
    - _Дополнение:_ Когда вы скачиваете чужую библиотеку, вам удобно видеть ее исходный код в IDE (с комментариями), а не декомпилированный байт-код. Этот плагин упаковывает ваши `.java` файлы в отдельный архив `*-sources.jar`, чтобы другие разработчики могли их читать.
        
4. **`maven-dependency-plugin`**: Мощный инструмент для работы с зависимостями.
    
    - Позволяет копировать нужные JAR-файлы зависимостей в отдельную папку при сборке, анализировать неиспользуемые зависимости или конфликты версий.

## 2. Сборка WAR-проекта (Веб-приложения)

Обычно Maven собирает код в **JAR** (Java Archive). Но если мы пишем классическое веб-приложение (например, на сервлетах или Spring MVC без встроенного сервера), нам нужен формат **WAR** (Web Application Archive).

- **Разница:** JAR — это просто архив с классами. WAR — это архив со строгой структурой папок (включая папку `WEB-INF`, файл `web.xml`, веб-страницы `.jsp` или `.html`), который предназначен для запуска внутри **Веб-контейнера** (например, Apache Tomcat).
    
- **Как включить:** В `pom.xml` нужно указать `<packaging>war</packaging>` (вместо `jar`).
    
- Сборкой такого архива занимается специальный `maven-war-plugin`.

## 3. Развертывание (Deploy) проектов

Собрать архив мало — его нужно куда-то доставить, чтобы он работал или им могли пользоваться другие. Этот процесс называется **Deploy** (Развертывание).

### А. Деплой библиотек

Если вы написали полезную библиотеку, вы можете выложить ее в репозиторий:

- Используется **`maven-deploy-plugin`**.
    
- Команда `mvn deploy` отправит вашу сборку в корпоративный репозиторий (Nexus / Artifactory) или в глобальный Maven Central, чтобы коллеги могли подключить ее через `<dependency>`.
    

### Б. Деплой веб-приложений (в Apache Tomcat)

Tomcat — самый популярный веб-сервер для Java-приложений. Maven умеет автоматически закидывать собранный `war` файл прямо в работающий Tomcat.

1. **Настройка сервера:** В Tomcat (в файле `tomcat-users.xml`) нужно создать пользователя с правами `manager-script`, чтобы Maven имел право по сети загружать файлы.
    
2. **Настройка Maven:** В файле `settings.xml` прописываются логин и пароль от Tomcat.
    
3. **Плагины:**
    
    - Можно использовать **Tomcat Maven Plugin** (напрямую работает с Tomcat).
        
    - Можно использовать **Cargo Plugin** — это универсальный плагин, который умеет деплоить не только в Tomcat, но и в GlassFish, WildFly, Jetty и другие серверы.
        

### В. Деплой с помощью IntelliJ IDEA (Локальная разработка)

Во время разработки приложения настраивать Maven-деплой долго. Проще делегировать это IDE:

1. Вы скачиваете и распаковываете Tomcat на свой компьютер.
    
2. В IDEA создаете конфигурацию запуска (Run/Debug Configurations -> Tomcat Server -> Local).
    
3. Указываете путь к папке с Tomcat.
    
4. На вкладке "Deployment" добавляете ваш проект как **Artifact** (обычно формата `war exploded` — распакованный архив, чтобы изменения в HTML/JSP применялись без перезапуска сервера на лету).

## 4. Повременные и полезные инструменты (GitHub и Docker)

В конце лекции упоминаются современные тенденции распространения кода.

- **Свой репозиторий на GitHub:**
    
    С помощью плагина **`site-maven-plugin`** можно автоматизировать процесс выгрузки вашей библиотеки, документации (JavaDoc) и отчетов о тестировании прямо на GitHub Pages или в релизы репозитория.
    
- **Интеграция с Docker:**
    
    В современную эпоху микросервисов мы редко деплоим WAR-файлы в отдельно стоящий Tomcat. Обычно приложение пакуется в JAR вместе со встроенным сервером (Spring Boot) и помещается в изолированный контейнер **Docker**.
    
    - Существуют специальные плагины (например, `dockerfile-maven-plugin` или современный `spring-boot-maven-plugin` с поддержкой Buildpacks).
        
    - Они позволяют по команде Maven не просто собрать `.jar`, но и сразу создать **Docker-образ (image)**, положить внутрь него Java, наше приложение, и отправить этот образ в хранилище (Docker Registry / Docker Hub).
