## 1. Введение: Зачем нужен Maven?

До появления систем сборки разработчикам приходилось вручную скачивать сторонние библиотеки (JAR-файлы), класть их в папку проекта, прописывать пути (classpath) и вручную компилировать исходный код. Это долго, неудобно и часто приводило к проблемам совместимости ("у меня на компьютере работает, а у тебя нет").

**Maven решает две главные задачи:**

1. **Управление зависимостями:** Он сам скачивает нужные библиотеки из интернета (и библиотеки, от которых зависят эти библиотеки).
    
2. **Автоматизация сборки:** По одной команде он может очистить проект, скомпилировать код, прогнать тесты и упаковать результат в готовый JAR или WAR файл.
    

---

## 2. Project Object Model (POM)

Основа любого Maven-проекта — файл **`pom.xml`**. Он всегда лежит в корневой папке проекта.

Это "паспорт" и "инструкция" для проекта. В нем описывается, как проект называется, от каких библиотек зависит и как его нужно собирать.

### Базовые координаты (GAV)

Каждый проект или библиотека в мире Maven имеет уникальный идентификатор, состоящий из трех параметров:

- **`groupId`**: Идентификатор организации или группы разработчиков (обычно это перевернутое доменное имя, например, `org.springframework`).
    
- **`artifactId`**: Название конкретного проекта или модуля (например, `spring-core`).
    
- **`version`**: Версия проекта (например, `5.3.9` или `1.0-SNAPSHOT`).

## 3. Стандартная структура Maven-проекта

Maven пропагандирует подход _"Convention over Configuration"_ (соглашение важнее конфигурации). Это значит, что если вы положите файлы в стандартные папки, вам не придется писать никаких настроек в `pom.xml`.

**Стандартная иерархия папок:**

- `src/main/java/` — Исходный код вашего приложения (ваши Java-классы).
    
- `src/main/resources/` — Ресурсы приложения (картинки, файлы настроек `.properties`, `.xml`).
    
- `src/test/java/` — Исходный код автотестов (например, JUnit).
    
- `src/test/resources/` — Ресурсы, нужные только для тестов.
    
- `target/` — Папка, куда Maven складывает результаты своей работы (скомпилированные `.class` файлы и итоговый JAR). _Эту папку обычно добавляют в `.gitignore`._
    
- `pom.xml` — Файл настроек.

## 4. Зависимости (Dependencies)

Если вашему проекту нужна сторонняя библиотека (например, для работы с JSON или базой данных), вы просто добавляете ее описание в `pom.xml` внутри блока `<dependencies>`.


``` XML
<dependencies>
    <dependency>
        <groupId>com.google.code.gson</groupId>
        <artifactId>gson</artifactId>
        <version>2.8.6</version>
    </dependency>
</dependencies>
```

**Откуда берутся зависимости?**

1. **Локальный репозиторий (`~/.m2/repository`):** Maven сначала ищет библиотеку на вашем компьютере.
    
2. **Центральный репозиторий (Maven Central):** Если локально библиотеки нет, Maven идет в интернет (на глобальный сервер `repo.maven.apache.org`), скачивает ее, сохраняет в локальный репозиторий и подключает к проекту.

## 5. Жизненный цикл сборки и Фазы (Phases)

Процесс сборки проекта в Maven разбит на строгие этапы — **фазы**. Фазы выполняются строго по порядку: нельзя выполнить упаковку, не скомпилировав код.

**Самые важные стандартные фазы (Lifecycle):**

1. **`clean`**: Удаляет папку `target/` со всеми результатами предыдущей сборки (очищает проект).
    
2. **`validate`**: Проверяет, что проект корректен и вся нужная информация доступна.
    
3. **`compile`**: Компилирует исходный код приложения (из `src/main/java`).
    
4. **`test`**: Запускает unit-тесты (из `src/test/java`). Если тесты упадут, сборка остановится.
    
5. **`package`**: Берет скомпилированный код и упаковывает его в архив (например, JAR или WAR).
    
6. **`verify`**: Выполняет дополнительные проверки (интеграционные тесты).
    
7. **`install`**: Устанавливает готовый пакет (JAR) в ваш **локальный** репозиторий (`.m2`). Теперь другие ваши локальные проекты смогут использовать его как зависимость.
    
8. **`deploy`**: Копирует готовый пакет на удаленный (корпоративный) сервер (например, Nexus или Artifactory), чтобы им могли пользоваться другие разработчики.
    

> **Пример:** Если вы запустите команду `mvn package`, Maven по очереди выполнит фазы: validate -> compile -> test -> package.

---

## 6. Maven Плагины (Plugins)

Maven сам по себе — это просто ядро, которое управляет фазами. Всю реальную работу делают **плагины**.

Каждая фаза привязана к определенному плагину (или цели плагина).

- _Компилирует код_ не сам Maven, а плагин `maven-compiler-plugin`.
    
- _Запускает тесты_ плагин `maven-surefire-plugin`.
    
- _Удаляет папку target_ плагин `maven-clean-plugin`.
    

Вы можете добавлять свои плагины в `pom.xml`, чтобы расширить возможности (например, плагин для генерации Javadoc или плагин Spring Boot для сборки исполняемого JAR).

## 7. Свойства (Properties)

В `pom.xml` можно объявлять переменные в блоке `<properties>`, чтобы не дублировать код.

**Зачем нужно:**

Чаще всего используется для управления версиями. Если у вас подключено 5 библиотек из фреймворка Spring, и у них должна быть одинаковая версия, вы выносите номер версии в свойство и ссылаетесь на него.


``` XML
<properties>
    <spring.version>5.3.9</spring.version>
</properties>
...
<version>${spring.version}</version> ```

Также есть встроенные переменные:
* `${basedir}` — путь к папке проекта.
* `${project.version}` — версия вашего проекта.
* `${project.build.directory}` — путь к папке `target`.
```
