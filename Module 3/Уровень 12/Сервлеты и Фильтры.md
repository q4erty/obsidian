## 1. Введение: Что такое Сервлет?

Веб-сервер (например, Apache) умеет отдавать только статические файлы (HTML, картинки). Чтобы сервер мог генерировать страницы динамически (например, выводить список товаров из базы данных), нужна программа, которая будет принимать запрос, выполнять Java-код и возвращать результат.

- **Сервлет (Servlet)** — это Java-класс, который расширяет возможности сервера. Он принимает HTTP-запрос от клиента, обрабатывает его (ходит в БД, считает бизнес-логику) и формирует HTTP-ответ.
    
- **Контейнер сервлетов (Servlet Container):** Сервлеты не работают сами по себе. Ими управляет специальная программа — контейнер (самый популярный — **Apache Tomcat**). Контейнер берет на себя всю рутину по работе с сетью, созданию потоков и жизненным циклом сервлетов.
    

---

## 2. Иерархия классов и интерфейсов

Чтобы создать свой сервлет, нужно реализовать определенные интерфейсы из пакета `javax.servlet` (или `jakarta.servlet` в новых версиях).

1. **Интерфейс `Servlet`**: Базовый интерфейс, описывающий жизненный цикл.
    
2. **Абстрактный класс `GenericServlet`**: Реализует интерфейс `Servlet`, но не привязан к конкретному сетевому протоколу.
    
3. **Абстрактный класс `HttpServlet`**: Наследник `GenericServlet`, специально заточенный под протокол HTTP. **Именно от него мы наследуемся** в 99% случаев.
    

---

## 3. Методы обработки HTTP-запросов (HttpServlet)

При наследовании от `HttpServlet` вам не нужно писать сетевой код. Вы просто переопределяете методы, соответствующие HTTP-методам (GET, POST, PUT, DELETE), которые мы изучали в предыдущих лекциях.

- **`doGet(HttpServletRequest req, HttpServletResponse resp)`** — вызывается при получении GET-запроса (например, когда пользователь просто открывает страницу).
    
- **`doPost(HttpServletRequest req, HttpServletResponse resp)`** — вызывается при получении POST-запроса (например, при отправке формы регистрации).
    
- **`doPut(...)`**, **`doDelete(...)`** и т.д.
    

> **Важно:** Существует метод `service()`. Именно он вызывается контейнером первым. Метод `service()` сам смотрит на тип пришедшего запроса и уже под капотом решает, какой метод вызвать: `doGet` или `doPost`. Обычно метод `service()` разработчики не переопределяют.

## 4. Объекты Request и Response

Каждый метод `doGet` или `doPost` принимает два важнейших объекта, которые контейнер (Tomcat) создает автоматически и передает в ваш метод.

### A. `HttpServletRequest` (Входящий запрос)

Содержит всю информацию, которую прислал клиент (браузер).

- `req.getParameter("name")` — получить параметр из URL или формы (например, `?name=Ivan`).
    
- `req.getHeader("User-Agent")` — прочитать HTTP-заголовки.
    
- `req.getCookies()` — получить куки пользователя.
    
- `req.getSession()` — получить текущую сессию пользователя (для сохранения состояния между запросами).
    

### B. `HttpServletResponse` (Исходящий ответ)

Используется для формирования ответа сервера.

- `resp.setContentType("text/html")` — сказать браузеру, какой тип данных мы возвращаем.
    
- `resp.setStatus(200)` — установить HTTP статус-код.
    
- `resp.getWriter().write("<html>...</html>")` — записать сам текст (HTML, JSON), который улетит в браузер.
    
- `resp.sendRedirect("/new-page")` — перенаправить пользователя на другой URL.

## 5. Жизненный цикл сервлета (Lifecycle)

Контейнер управляет сервлетами по строгим правилам. Сервлеты создаются в **единственном экземпляре (Singleton)**, и этот один объект обрабатывает запросы от всех пользователей в разных потоках.

1. **Загрузка и создание (Instantiate):** Контейнер создает объект сервлета (обычно при первом обращении к нему).
    
2. **Инициализация — метод `init()`:** Вызывается ровно один раз после создания. Здесь можно открыть соединение с базой данных или прочитать настройки.
    
3. **Обработка запросов — метод `service()`:** Вызывается каждый раз, когда приходит новый запрос (и вызывает `doGet`/`doPost`). _Работает в многопоточной среде, поэтому нельзя сохранять пользовательские данные в поля класса сервлета!_
    
4. **Уничтожение — метод `destroy()`:** Вызывается один раз перед тем, как контейнер выгрузит сервлет из памяти (например, при остановке сервера). Здесь нужно закрыть коннекты к БД и освободить ресурсы.

## 6. Конфигурация: web.xml vs Аннотации

Чтобы Tomcat понял, по какому URL-адресу нужно вызывать ваш сервлет, его нужно зарегистрировать (сделать маппинг).

- **Старый способ (Deployment Descriptor):** Прописывание настроек в специальном XML-файле `WEB-INF/web.xml`. Это громоздко, но полезно, если вы не можете менять исходный код сервлета.
    
- **Новый способ (Java EE 6+):** Аннотация **`@WebServlet`**. Вы просто вешаете её над классом:
    
    Java
    
    ```
    @WebServlet("/hello")
    public class HelloServlet extends HttpServlet { ... }
    ```
    
    Теперь любой запрос на адрес `http://localhost:8080/ваше_приложение/hello` попадет в этот сервлет.

## 7. Фильтры (Filters)

Фильтр — это Java-компонент, который стоит "перед" сервлетом. Он перехватывает запрос до того, как тот попадет в сервлет, и может перехватить ответ до того, как он уйдет клиенту.

- **Зачем нужны:**
    
    - Проверка авторизации (если пользователь не залогинен, фильтр не пустит его к сервлету профиля, а сразу перенаправит на страницу логина).
        
    - Логирование всех входящих запросов.
        
    - Сжатие данных или изменение кодировки.
        
- **Интерфейс `Filter`**:
    
    - `init(FilterConfig config)` — инициализация фильтра.
        
    - `doFilter(ServletRequest req, ServletResponse resp, FilterChain chain)` — главная логика. Если проверка пройдена, фильтр вызывает `chain.doFilter(req, resp)`, чтобы передать запрос дальше по цепочке к сервлету.
        
    - `destroy()` — очистка ресурсов.
