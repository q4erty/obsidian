Класс `Object` — это корень всей иерархии классов в Java. Любой класс, который вы создаете, неявно наследуется от него, а значит, получает набор базовых методов.

---
## 1. Метод `toString()`

Этот метод используется для получения строкового представления объекта.

- **Стандартная реализация:** Возвращает строку вида `ИмяКласса@ХешКод` (например, `java.lang.Object@12F456`).
    
- **Зачем переопределять:** Чтобы выводить в консоль или логи понятную информацию об объекте (например, значения его полей), а не технический адрес.


---

## 2. Методы `equals()` и `hashCode()`

Эта пара методов критически важна для сравнения объектов и работы с коллекциями (например, `HashMap`, `HashSet`).

### `equals(Object obj)`

- **Цель:** Определяет логическую эквивалентность объектов (идентичны ли они внутри).
    
- **Стандартная реализация:** Сравнивает только ссылки (`this == obj`), то есть проверяет, является ли это одним и тем же объектом в памяти.
    
- **Рекомендация:** Разработчик должен переопределять этот метод, чтобы сравнивать объекты по значимым полям (например, по ID или имени).


### `hashCode()`

- **Цель:** Возвращает целочисленное значение (хеш-код) для оптимизации поиска в хеш-таблицах.
    
- **Контракт (правила связи с equals):**
    
    1. Если объекты равны по `equals()`, их `hashCode()` **обязаны** быть одинаковыми.
        
    2. Если хеш-коды разные, объекты гарантированно разные.
        
    3. Если хеш-коды равны, объекты _могут_ быть разными (коллизия), тогда вступает в дело `equals()`.
    

> **Важно:** Если вы переопределяете `equals`, вы **обязаны** переопределить и `hashCode`. Иначе объекты будут теряться в коллекциях.

---

## 3. Метод `getClass()` и Reflection

- **Назначение:** Возвращает объект типа `Class`, который содержит информацию о структуре текущего класса (поля, методы, конструкторы).
    
- **Reflection (Рефлексия):** Механизм, позволяющий программе изучать саму себя. Через объект `Class` можно узнать имя класса, получить список методов, создать новый экземпляр (`newInstance`) или вызвать метод по имени.
    
    - _Пример:_ `String.class.getMethod("length")` находит метод, который потом можно вызвать.
    

---

## 4. Метод `clone()`

- **Цель:** Создание дубликата (копии) объекта.
    
- **Особенности:**
    
    - Стандартная реализация создает **поверхностную копию** (копируются значения полей и ссылки, но не сами вложенные объекты).
        
    - Для корректной работы класс должен реализовывать интерфейс-маркер `Cloneable`. Если интерфейса нет — вылетит ошибка `CloneNotSupportedException`.
    

---

## 5. Метод `finalize()`

- **Назначение:** Вызывается сборщиком мусора (Garbage Collector) перед уничтожением объекта, чтобы освободить внешние ресурсы (файлы, потоки).
    
- **Проблемы:** Нет гарантии, когда он будет вызван и будет ли вызван вообще.
    
- **Современная альтернатива:** Вместо `finalize` рекомендуется использовать конструкцию `try-with-resources` (появилась в Java 7).


---

## 6. Многопоточность: `wait()`, `notify()`, `notifyAll()`

Эти методы используются для синхронизации потоков (нитей). Они работают только внутри блока `synchronized`, когда поток владеет «монитором» объекта.

- **`wait()`**: Освобождает монитор и переводит текущий поток в режим ожидания («ставит на паузу»), пока другой поток его не разбудит.
    
    - Есть версии с таймаутом (`wait(long timeout)`), когда поток просыпается сам через заданное время.
    
- **`notify()`**: Размораживает **одну** случайную нить, ожидающую на этом мониторе.
    
- **`notifyAll()`**: Размораживает **все** нити, ожидающие на этом мониторе.

## 7. Mutable и Immutable объекты

В лекции также затрагивается концепция изменяемости объектов.

- **Mutable (Изменяемые):** Объекты, состояние которых можно изменить после создания (сеттерами или прямым доступом к полям).
    
- **Immutable (Неизменяемые):** Объекты, которые нельзя изменить после создания. Любая операция изменения возвращает **новый** объект.
    
    - _Классический пример:_ Класс `String`. Метод `toUpperCase()` не меняет исходную строку, а создает новую в верхнем регистре.
        
    - **Плюсы Immutable:** Потокобезопасны (можно использовать в разных нитях без синхронизации) и проще в реализации.
