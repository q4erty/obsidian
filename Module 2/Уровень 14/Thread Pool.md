## 1. Зачем нужен Thread Pool?

Создание нового потока (`new Thread()`) — это **дорогостоящая операция** для операционной системы.

- Если создавать новый поток на каждую мелкую задачу, система потратит больше ресурсов на создание/удаление потоков, чем на выполнение самой работы.
    
- **Решение:** Использовать **Thread Pool** (пул потоков). Это набор уже созданных («разогретых») потоков, которые не умирают после выполнения задачи, а ждут следующую.


**Архитектура Executor Framework (Java 5+):**

- **`Executor`**: Самый простой интерфейс с одним методом `execute(Runnable)`. Просто «выполнить задачу».
    
- **`ExecutorService`**: Расширенный интерфейс. Умеет не только выполнять задачи, но и управлять жизненным циклом пула (остановка, проверка статуса) .
    
- **`ThreadPoolExecutor`**: Основной класс-реализация, который связывает задачи и рабочие потоки. Вы даете ему задачи (Runnables), а он сам решает, какому потоку их отдать.

## 2. Основные виды пулов (Класс `Executors`)

Для удобства создания пулов существует фабричный класс `Executors`. В нем есть готовые методы для самых частых сценариев .

### А. Fixed Thread Pool (Фиксированный)

`Executors.newFixedThreadPool(int n)`

- Создает пул с **фиксированным** количеством потоков (например, 10).
    
- **Логика:**
    
    - Одновременно работают максимум `n` потоков.
        
    - Если задач больше, чем потоков, они **ждут в очереди**.
        
    - Если поток упадет с ошибкой, пул создаст новый ему на замену.
        
    - Потоки живут, пока пул не будет явно закрыт.
    

### Б. Single Thread Executor (Одиночный)

`Executors.newSingleThreadExecutor()`

- Пул, состоящий всего из **одного** потока.
    
- **Зачем нужен:** Гарантирует, что задачи будут выполняться **последовательно** (одна за другой), а не параллельно.
    
- **Надежность:** Если единственный поток упадет, автоматически создастся новый и продолжит разгребать очередь.

### В. Cached Thread Pool (Кэширующий)

`Executors.newCachedThreadPool()`

- Самый гибкий пул.
    
- **Логика:**
    
    - Не имеет фиксированного размера.
        
    - Если есть свободный поток — отдает задачу ему.
        
    - Если все заняты — **создает новый поток**.
        
    - Если поток долго (обычно 60 сек) бездельничает — он удаляется.
    
- **Применение:** Идеален для большого количества **коротких** (легких) задач.
    
- **SynchronousQueue:** Внутри этого пула используется специальная очередь. Она не хранит элементы: "положить" задачу в очередь можно только если прямо сейчас есть поток, готовый её "забрать" .

### Г. Work Stealing Pool (Крадущий работу)

`Executors.newWorkStealingPool()`

- Основан на алгоритме `fork/join`.
    
- **Логика:**
    
    - Каждый поток имеет свою личную очередь задач (deque).
        
    - Если один поток освободился, а у другого в очереди завал, свободный поток может **«украсть»** задачу у занятого.
    
- **Параллелизм:** По умолчанию создает столько потоков, сколько ядер у процессора .

### Д. Scheduled Thread Pool (Планировщик)

`Executors.newScheduledThreadPool(int n)`

- Аналог системного планировщика (Cron) или `Timer`.
    
- Позволяет запускать задачи **с задержкой** или **периодически** (например, "запускать бэкап каждые 24 часа").
    
- Используется для сервисных фоновых задач.

## 3. Настройка создания потоков (ThreadFactory)

Если вам не нравятся стандартные потоки (например, вы хотите дать им понятные имена типа "MyPool-Worker-1" или изменить приоритет), вы можете передать в конструктор пула свою реализацию интерфейса `ThreadFactory` .

- Это позволяет настраивать приоритеты, делать потоки демонами и устанавливать обработчики ошибок (`UncaughtExceptionHandler`).

## 4. Локальные данные потока

### ThreadLocal

Иногда нужно, чтобы у каждого потока была **своя собственная** копия переменной, невидимая для других.

- `ThreadLocal` создает отдельную область видимости для потока .
    
- Методы `get()` и `set()` работают с значением, привязанным именно к текущему потоку (как `Map<Thread, Value>`).
    
- **Пример:** Хранение транзакции к базе данных или текущей сессии пользователя.

### ThreadLocalRandom

`java.util.concurrent.ThreadLocalRandom` (с Java 7).

- Обычный `Random` при работе из нескольких потоков работает медленно, так как потоки "толкаются", пытаясь обновить внутреннее состояние генератора (seed).
    
- `ThreadLocalRandom` изолирован для каждого потока, поэтому работает быстрее в многопоточной среде .
    
- Генерируемые числа в одном потоке не зависят от другого.
