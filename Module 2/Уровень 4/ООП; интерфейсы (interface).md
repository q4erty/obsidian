
## 1. Что такое интерфейс

**Интерфейс** — это:

> контракт, который описывает **что класс должен уметь**,  
> но **не говорит, как именно он это делает**

Проще:

- интерфейс — это набор требований
    
- класс, который его реализует, **обязан выполнить эти требования**


---

### Объявление интерфейса

```java
public interface Swimmable {
    void swim();
}
```

📌 В интерфейсе **не пишут реализацию** (классически).

---

## 2. Зачем нужны интерфейсы

Интерфейсы нужны, чтобы:

- добиться **абстракции**
    
- обеспечить **слабую связанность**
    
- обойти ограничение Java на множественное наследование
    
- писать код, зависящий от **поведения**, а не от класса


---

## 3. Реализация интерфейса

Класс **реализует** интерфейс с помощью `implements`.

```java
public class Duck implements Swimmable {
    @Override
    public void swim() {
        System.out.println("Плывем");
    }
}
```

📌 Важно:

- все методы интерфейса **обязаны быть реализованы**
    
- иначе класс должен быть `abstract`


---

## 4. Интерфейс ≠ абстрактный класс

Это **очень частый вопрос**.

|Интерфейс|Абстрактный класс|
|---|---|
|описывает _что делать_|описывает _что и частично как_|
|нет состояния (обычно)|может иметь поля|
|множественная реализация|одиночное наследование|
|`implements`|`extends`|

📌 Интерфейс — **более сильная абстракция**.

---

## 5. Множественная реализация интерфейсов

### Почему это важно

Java **не разрешает** множественное наследование классов,  
но **разрешает** реализовывать несколько интерфейсов.

```java
public class Duck implements FlyingBird, Waterfowl {
    @Override
    public void fly() {
        System.out.println("Летим!");
    }

    @Override
    public void swim() {
        System.out.println("Плывем!");
    }
}
```

📌 Это безопасно, потому что:

- интерфейсы не хранят состояние
    
- нет конфликта данных


---

## 6. Методы интерфейса (важные правила)

### По умолчанию методы интерфейса:

- `public`
    
- `abstract`


Даже если это **не написано явно**:

```java
void swim();
// на самом деле: public abstract void swim();
```

---

### Поля интерфейса

Все поля интерфейса всегда:

- `public`
    
- `static`
    
- `final`


```java
int MAX_SPEED = 120;
// public static final int MAX_SPEED = 120;
```

📌 Интерфейс **не хранит состояние объекта**.

---

## 7. default-методы интерфейсов

### Что это

**default-метод** — это метод интерфейса **с реализацией**.

```java
public interface Car {
    default void gas() {
        System.out.println("Газуем");
    }
}
```

---

### Переопределение default-методов

Класс может переопределить default-метод.

```java
public class UnusualCar implements Car {
    @Override
    public void gas() {
        System.out.println("Эта машина газует по-другому!");
    }
}
```

📌 Default-методы:

- появились, чтобы **расширять интерфейсы**
    
- не ломая старый код


---

## 8. Конфликты default-методов

Если класс реализует **два интерфейса с одинаковым default-методом**:

➡️ **компилятор потребует переопределение**

```java
class MyClass implements A, B {
    @Override
    public void test() {
        A.super.test();
    }
}
```

📌 Нужно явно указать, **какую реализацию использовать**.

---

## 9. Интерфейсы и полиморфизм

Интерфейсы — **основа полиморфизма в Java**.

```java
Swimmable s = new Duck();
s.swim();
```

📌 Код:

- не знает конкретный класс
    
- работает через поведение


---

## 10. Интерфейс как тип данных

Можно:

```java
Swimmable s;
```

Но нельзя:

```java
new Swimmable(); // ошибка
```

📌 Интерфейс:

- нельзя инстанцировать
    
- но можно использовать как тип ссылки


---

## 11. Когда использовать интерфейс

Используй интерфейс, если:

- классы **не связаны логически**, но имеют общее поведение
    
- нужна множественная реализация
    
- важно API и контракт
    
- нужен слабосвязанный код


---

## 12. Когда НЕ стоит использовать интерфейс

- если есть общая логика и состояние → абстрактный класс
    
- если связь «is-a» очевидна → наследование
