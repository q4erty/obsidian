## 1. Что такое ООП

**Объектно-ориентированное программирование (ООП)** — это парадигма программирования, в которой программа строится из **объектов**, взаимодействующих друг с другом.

Объект:

- хранит **данные** (состояние)
    
- выполняет **действия** (поведение)


ООП направлено на:

- упрощение структуры программы
    
- снижение количества ошибок
    
- удобство поддержки и расширения кода


---

## 2. Основные принципы ООП

ООП основано на **четырёх принципах**:

1. Инкапсуляция
    
2. Абстракция
    
3. Наследование
    
4. Полиморфизм


Все они работают **вместе** и приводят к:

- слабой связанности
    
- чёткой ответственности классов и методов


---

## 3. Класс и объект

### Класс

**Класс** — это шаблон (описание), по которому создаются объекты.

Класс содержит:

- поля
    
- методы
    
- конструкторы


```java
class User {
    String name;
    int age;

    void sayHello() {
        System.out.println("Привет");
    }
}
```

---

### Объект

**Объект** — конкретный экземпляр класса.

```java
User user = new User();
user.name = "Alex";
```

📌 Каждый объект имеет собственные данные, но общие методы.

---

## 4. Инкапсуляция

### Определение

**Инкапсуляция** — это сокрытие внутренней реализации класса и предоставление доступа к данным **только через методы**.

Цель инкапсуляции:

- защита данных
    
- контроль изменений
    
- снижение связанности


---

### Модификаторы доступа

|Модификатор|Уровень доступа|
|---|---|
|`private`|только внутри класса|
|`default`|внутри пакета|
|`protected`|внутри пакета + наследники|
|`public`|отовсюду|

---

### private

- `private` поля и методы **не наследуются**
    
- доступны только внутри класса


```java
private int balance;
```

---

### Геттеры и сеттеры

Используются для доступа к `private` полям.

```java
public int getBalance() {
    return balance;
}

public void setBalance(int balance) {
    if (balance >= 0) {
        this.balance = balance;
    }
}
```

📌 Через сеттеры можно:

- проверять данные
    
- запрещать некорректные изменения


---

## 5. Абстракция

### Определение

**Абстракция** — это выделение **главных характеристик объекта** и сокрытие деталей реализации.

Важно:

- _что_ объект делает
    
- _как_ он это делает — скрыто


---

### Абстракция и упрощение

Абстракция позволяет:

- работать с объектом, не зная деталей
    
- уменьшать сложность системы


---

### Абстракция и инкапсуляция (разница)

|Инкапсуляция|Абстракция|
|---|---|
|скрывает данные|скрывает сложность|
|private + методы|интерфейсы, абстрактные классы|
|защита|упрощение|

---

## 6. Наследование

### Определение

**Наследование** — механизм ООП, при котором один класс получает поля и методы другого.

```java
class Animal {
    void eat() {}
}

class Dog extends Animal {
}
```

---

### Что наследуется

✔️ наследуются:

- `public`
    
- `protected`
    
- `default` (в том же пакете)


❌ не наследуются:

- `private`
    
- конструкторы


---

### Ограничения наследования

- нельзя наследовать от `final` класса
    
- нельзя переопределять `final` методы
    
- Java поддерживает **одиночное наследование классов**


---

## 7. static и наследование

### static элементы

`static`:

- принадлежат **классу**, а не объекту
    
- не участвуют в полиморфизме


---

### Почему static методы нельзя переопределять

- static методы **не переопределяются**
    
- происходит **скрытие методов (method hiding)**


```java
class Parent {
    static void test() {
        System.out.println("Parent");
    }
}

class Child extends Parent {
    static void test() {
        System.out.println("Child");
    }
}
```

```java
Parent p = new Child();
p.test(); // Parent
```

📌 Метод выбирается по **типу ссылки**, а не объекта.

---

## 8. Полиморфизм

### Определение

**Полиморфизм** — это способность объекта по-разному реагировать на один и тот же вызов метода.

Работает только:

- с нестатическими методами
    
- с переопределением


---

### Переопределение методов

```java
class Animal {
    void sound() {
        System.out.println("Звук");
    }
}

class Cat extends Animal {
    @Override
    void sound() {
        System.out.println("Мяу");
    }
}
```

---

### Полиморфизм в работе

```java
Animal a = new Cat();
a.sound(); // Мяу
```

📌 Метод выбирается **во время выполнения программы**.

---

## 9. Ключевое слово super

### super.method()

Используется для вызова метода родительского класса.

```java
@Override
void sound() {
    super.sound();
    System.out.println("Гав");
}
```

---

### super и конструкторы

- `super()` вызывается **первой строкой конструктора**
    
- используется для передачи параметров родителю


---

## 10. Слабая связанность (Low Coupling)

### Связанность

**Связанность** — степень зависимости одного класса от другого.

- сильная связанность → плохо
    
- слабая связанность → хорошо


---

### Слабая связанность

**Слабая связанность** — это когда:

- классы минимально зависят друг от друга
    
- изменения в одном классе не ломают другие


Достигается за счёт:

- инкапсуляции
    
- абстракции
    
- полиморфизма


---

### Пример

Зависимость от абстракции, а не от реализации.

```java
interface Engine {
    void start();
}
```

---

## 11. Чёткая ответственность и чёткие функции

### Принцип

- один класс — одна зона ответственности
    
- один метод — одна логическая задача


---

### Почему это важно

- код легче читать
    
- проще тестировать
    
- проще расширять


---

### Плохой пример

```java
void processUser() {
    // проверка
    // сохранение
    // отправка email
}
```

---

### Хороший пример

```java
void validateUser() {}
void saveUser() {}
void sendEmail() {}
```
