Эта лекция посвящена переходу от ручного управления потоками (`new Thread().start()`) к использованию профессионального фреймворка **ExecutorService**, который управляет пулами потоков. Также рассматриваются продвинутые интерфейсы для работы с результатами выполнения задач.

---

## 1. Управление группами и приоритетами (Legacy)

Прежде чем перейти к пулам потоков, в лекции рассматриваются базовые механизмы управления.

### ThreadGroup (Группы потоков)

Это механизм организации потоков в иерархическую структуру (дерево).

- **Зачем нужно:** Чтобы управлять сразу пачкой потоков. Например, ограничить права доступа или остановить все потоки группы одной командой.
    
- **Безопасность:** Поток может влиять только на потоки своей группы или подгрупп.

### Приоритеты потоков

У каждого потока есть приоритет — число от **1** (MIN_PRIORITY) до **10** (MAX_PRIORITY). Стандартный приоритет — **5** (NORM_PRIORITY).

- **Как это работает:** Вы можете подсказать планировщику (OS Scheduler), что один поток важнее другого (`thread.setPriority(8)`).
    
- **Важный нюанс:** Приоритеты носят **рекомендательный характер**.
    
    - Java не гарантирует, что поток с приоритетом 10 запустится раньше потока с приоритетом 1.
        
    - Всё зависит от операционной системы. Нельзя строить логику программы, полагаясь на строгий порядок выполнения через приоритеты.

## 2. Интерфейс `Callable<V>` vs `Runnable`

Ранее мы использовали `Runnable`. У него есть два недостатка: метод `run()` ничего не возвращает (`void`) и не может выбрасывать проверяемые исключения (`throws Exception`).

В Java 5 появился интерфейс **`Callable<V>`**:

- **Метод:** `V call() throws Exception`
    
- **Возвращает результат:** Да (типа V).
    
- **Выбрасывает исключения:** Да.

|**Характеристика**|**Runnable**|**Callable**|
|---|---|---|
|Метод|`run()`|`call()`|
|Возвращаемое значение|`void` (нет)|Объект типа `V`|
|Исключения (Checked)|Нельзя|Можно (`throws Exception`)|
|Использование|`new Thread(runnable)`|Только через `ExecutorService`|

## 3. ExecutorService (Пулы потоков)

Создавать новый поток (`new Thread`) на каждую задачу — **дорого**. Это требует памяти и времени процессора.

**ExecutorService** решает эту проблему, используя **Пул потоков (Thread Pool)**.

- **Суть:** Создается фиксированное количество потоков (например, 5). Они не умирают после выполнения задачи, а ждут следующую. Это похоже на очередь в кассе: кассир один, а покупателей много.
    
- **Фабричный метод:** Для создания пулов используется класс-фабрика `Executors`.
    
    - `Executors.newFixedThreadPool(10)` — пул ровно из 10 потоков.
        
    - `Executors.newCachedThreadPool()` — резиновый пул (создает новые, если нужно, удаляет лишние, если они простаивают).
        
    - `Executors.newSingleThreadExecutor()` — пул из одного потока (гарантия последовательного выполнения).

## 4. Получение результата: Future

Когда мы отдаем задачу `Callable` в `ExecutorService`, она выполняется асинхронно (в другом потоке). Как забрать результат, когда он будет готов?

Для этого используется объект-заглушка **`Future`** (Будущее).

1. Вы отправляете задачу: `Future<String> result = executor.submit(task);`
    
2. Программа идет дальше, не блокируясь.
    
3. Когда результат нужен, вы вызываете `result.get()`.

**Методы Future:**

- **`get()`**: Блокирует текущий поток и ждет, пока задача не завершится. Возвращает результат или кидает исключение.
    
- **`isDone()`**: Проверяет, завершилась ли задача (true/false).
    
- **`cancel(true)`**: Пытается отменить выполнение задачи.

## 5. Основные методы ExecutorService

### Запуск задач

1. **`execute(Runnable)`**:
    
    - "Запустил и забыл".
        
    - Ничего не возвращает (`void`). Если задача упала с ошибкой, вы об этом можете не узнать.
        
2. **`submit(Runnable)`** или **`submit(Callable)`**:
    
    - Возвращает `Future`.
        
    - Позволяет контролировать выполнение и ловить исключения.
    

### Массовый запуск

1. **`invokeAll(Collection tasks)`**:
    
    - Запускает **все** задачи из коллекции.
        
    - Возвращает список `List<Future>`, когда **все** они завершатся.
    
2. **`invokeAny(Collection tasks)`**:
    
    - Запускает задачи и ждет, пока завершится **хотя бы одна** (первая успешная).
        
    - Возвращает готовый результат (не Future), остальные задачи отменяются.

## 6. Остановка ExecutorService

Пул потоков не закрывается автоматически, даже если задачи кончились (он ждет новых). Программа не завершится, пока работает Executor.

**Способы остановки:**

1. **`shutdown()`** (Вежливая остановка):
    
    - Новые задачи больше не принимаются.
        
    - Текущие и стоящие в очереди задачи доделываются.
        
    - Как только все задачи выполнены, пул умирает.
    
2. **`shutdownNow()`** (Грубая остановка):
    
    - Пытается остановить текущие потоки (через `interrupt`).
        
    - Возвращает список задач, которые были в очереди, но не успели запуститься.
    
3. **`awaitTermination(time, unit)`**:
    
    - Блокирует текущий поток и ждет (как `join`), пока пул не закроется или не истечет тайм-аут.
        
    - Обычно используется в комбинации: "Сначала `shutdown()`, потом `awaitTermination` ждем 1 минуту, если не успели — `shutdownNow()`".
    

---

**Пример использования (шаблон):**

``` java
ExecutorService pool = Executors.newFixedThreadPool(2);

// Задача
Callable<String> task = () -> {
    Thread.sleep(1000);
    return "Готово!";
};

// Отправка
Future<String> future = pool.submit(task);

// ... делаем другие дела ...

try {
    // Получение результата (здесь поток заблокируется, если задача еще идет)
    String result = future.get(); 
    System.out.println(result);
} catch (Exception e) {
    e.printStackTrace();
} finally {
    // Обязательно закрываем пул
    pool.shutdown();
}
```
