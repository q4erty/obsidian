В этой лекции рассматриваются механизмы проверки типов, их приведения (casting), а также эволюция оператора `switch` и улучшения синтаксиса в новых версиях Java.

## 1. Оператор `instanceof`

Этот оператор используется для проверки того, принадлежит ли объект к определенному классу, является ли его наследником или реализует ли интерфейс.

- **Синтаксис:** `объект instanceof Класс`
    
- **Результат:** Возвращает `true` или `false`.


### Как это работает:

1. **Прямое совпадение:** Если переменная хранит ссылку на объект указанного типа.
    
    - _Пример:_ `Object o = new Integer(3);` -> `o instanceof Integer` вернет **true**.
        
2. **Наследование:** Если объект является экземпляром класса-наследника.
    
    - _Правило:_ `a instanceof B` вернет `true`, если класс объекта `a` унаследован от `B`.
    
3. **Интерфейсы:** Если объект реализует указанный интерфейс.
    
4. **Несовпадение:**
    
    - _Пример:_ `Object o = "Мама";` -> `o instanceof Integer` вернет **false**, так как строка — это не число.
    

> **Дополнение:** Важно помнить, что `null instanceof ЛюбойКласс` всегда возвращает `false`. Это защищает от `NullPointerException` при проверке.

## 2. Приведение типов (Type Casting)

В Java переменная может быть объявлена с одним типом, а хранить объект другого (совместимого) типа. Процесс перехода между типами называется приведением.

### Восходящее преобразование (Upcasting / Расширение типа)

Это движение **вверх** по иерархии наследования (к более общему типу, например, к `Object`).

- Происходит **автоматически** (неявно).
    
- **Суть:** Объект класса-наследника содержит все методы родителя, поэтому его безопасно сохранить в переменную родительского типа.
    
- **Минус:** Теряется доступ к методам, которые есть только у наследника (специфичным методам).


### Нисходящее преобразование (Downcasting / Сужение типа)

Это движение **вниз** по иерархии (к конкретному типу).

- Требует **явного** указания типа: `(String) obj`.
    
- **Риск:** Если объект на самом деле не принадлежит к этому типу, возникнет ошибка `ClassCastException`.
    
- **Зачем нужно:** Чтобы получить доступ к методам конкретного класса, которые были "скрыты" при Upcasting.

## 3. Эволюция Switch (Switch Expression)

В презентации рассматривается переход от классического `switch statement` к более современному `switch expression` (появился официально в Java 14).

### Старый подход (Switch Statement)

Используется двоеточие `:` и слово `break`. Если забыть `break`, выполнение "провалится" в следующий кейс (fall-through).

``` java
switch (product) {
    case "Apple": 
        type = "Fruit"; 
        break; // Обязательно!
    ...
}
```

### Новый подход (Switch Expression)

Использует **Arrow syntax** (`->`). Это выражение, то есть оно **возвращает результат**, который можно сразу присвоить переменной или вернуть через `return`.

- **Преимущества:**
    
    - Не нужен `break` (нет проваливания).
        
    - Можно перечислять несколько значений через запятую:                                                 `case "Apple", "Peach" -> ...`
        
    - Компактный код.
    

``` java
// Пример Switch Expression
String type = switch (product) {
    case "Apple", "Peach" -> "Fruit";
    case "Raspberry" -> "Berry";
    default -> "other";
};
```

### Ключевое слово `yield`

Если в новом `switch` (после стрелочки `->`) нужно выполнить **блок кода** (несколько строк), а не просто вернуть значение, используются фигурные скобки `{}`. Чтобы вернуть значение из такого блока, вместо `return` используется слово **`yield`**.

- `break` выбрасывал из switch-а.
    
- `yield` возвращает значение из switch-а (как `return` для функции, но внутри switch).

``` java
case "Apple" -> {
    System.out.println("This is fruit");
    yield "Fruit"; // Возвращаем значение "Fruit"
}
```

## 4. Pattern Matching для `instanceof` (Java 14+)

Это синтаксический сахар, который убирает лишний код при проверке типов и кастинге (Downcasting).

**Старый ("некрасивый") способ:**

Сначала проверяем тип, потом приводим его вручную, чтобы вызвать метод.

``` java
if (s instanceof String) {
    ((String) s).toLowerCase(); // Громоздкое явное приведение
}
```

**Новый способ (Pattern Matching):**

Мы объявляем переменную прямо в условии. Если проверка проходит, переменная `s` сразу создается с нужным типом `String`.

``` java
if (o instanceof String s) { // Проверили и сразу создали 's' типа String
    s.toLowerCase();         // Можно сразу использовать методы String
}
```
