## 1. Протокол TCP (Transmission Control Protocol)

**TCP** — это протокол управления передачей данных, основанный на установлении соединения.

- **Главная особенность:** Надежность. Перед тем как начать передавать данные, два компьютера («хоста») должны «созвониться» и установить канал связи.
    
- **Гарантии TCP:**
    
    1. **Доставка:** Гарантирует, что данные дойдут до получателя. Если пакет потерялся, TCP отправит его снова автоматически.
        
    2. **Порядок:** Данные придут в том же порядке, в котором были отправлены (1, 2, 3...), а не вперемешку.
        
    3. **Целостность:** Данные не будут повреждены.

## 2. Понятие Socket (Сокет)

Сокет — это конечная точка (endpoint) для обмена данными между двумя программами по сети.

Программно сокет — это комбинация **IP-адреса** (куда стучаться) и **Порта** (в какую дверь стучаться).

### Клиент-Серверная архитектура в Java (TCP)

В Java для работы с TCP используются классы из пакета `java.net`.

#### A. Сервер (`ServerSocket`)

Сервер — это тот, кто ждет подключения.

1. Создается объект `ServerSocket(port)`. Он «слушает» указанный порт на компьютере.
    
2. Вызывается метод **`accept()`**.
    
    - **Важно:** Этот метод **блокирующий**. Программа останавливается на этой строчке и ждет, пока кто-нибудь не постучится.
    
3. Как только клиент подключился, метод `accept()` возвращает объект обычного `Socket` для общения с этим конкретным клиентом.
    

#### B. Клиент (`Socket`)

Клиент — это тот, кто инициирует общение.

1. Создается объект `Socket("ip_address", port)`.
    
2. Если сервер доступен, соединение устанавливается мгновенно.


#### C. Обмен данными (Streams)

После соединения и у клиента, и у сервера есть объект `Socket`. Обмен данными происходит через **потоки ввода-вывода** (как при чтении файлов):

- `socket.getInputStream()` — чтобы читать то, что прислал собеседник.
    
- `socket.getOutputStream()` — чтобы отправлять данные собеседнику.


> **Аналогия TCP:** Это телефонный звонок. Вы набираете номер, собеседник поднимает трубку («алло»), устанавливается связь, и только потом вы говорите. Вы точно знаете, что вас слышат.

## 3. Протокол UDP (User Datagram Protocol)

**UDP** — это протокол пользовательских датаграмм. Он работает **без установления соединения**.

- **Главная особенность:** Скорость и простота («Выстрелил и забыл»).
    
- **Как работает:** Данные разбиваются на пакеты (датаграммы) и отправляются в сеть. Отправителю всё равно, дошли они или нет.
    
- **Минусы:**
    
    1. **Нет гарантий:** Пакеты могут потеряться, и никто об этом не узнает.
        
    2. **Хаос:** Пакеты могут прийти не по порядку (отправили 1-2-3, пришло 3-1-2).
        
    3. **Дубликаты:** Один пакет может прийти дважды.
    

### Реализация в Java (UDP)

Здесь нет понятий `InputStream` или `OutputStream`. Работа идет с пакетами.

1. **`DatagramPacket`** (Письмо): Класс-контейнер. Содержит:
    
    - Массив байт (сами данные).
        
    - IP-адрес получателя.
        
    - Порт получателя.
    
2. **`DatagramSocket`** (Почтовый ящик/Почтальон): Отвечает за отправку и прием пакетов.
    
    - Метод `send(packet)`.
        
    - Метод `receive(packet)`.
    

> **Аналогия UDP:** Это обычная почта или голубиная почта. Вы отправляете письмо. Дойдет оно? Возможно. Когда? Неизвестно. В каком порядке придут письма, если отправить пачку? Как повезет.

## 4. Сравнение TCP и UDP (Ключевой слайд)

В презентации приводится таблица выбора протокола.

| **Характеристика** | **TCP**                     | **UDP**                          |
| ------------------ | --------------------------- | -------------------------------- |
| **Соединение**     | Есть (Connection-oriented)  | Нет (Connection-less)            |
| **Надежность**     | Высокая (гарантия доставки) | Низкая (пакеты могут теряться)   |
| **Порядок данных** | Гарантирован                | Не гарантирован                  |
| **Скорость**       | Медленнее (из-за проверок)  | Быстрее (нет накладных расходов) |
| **Тяжесть**        | Тяжеловесный                | Легковесный                      |

### Где что использовать?

**Выбираем TCP, если важна точность:**

- Отправка электронной почты (нельзя потерять половину письма).
    
- Передача файлов (файл должен скачаться целиком).
    
- Просмотр веб-страниц (HTTP/HTTPS работают поверх TCP).
    
- Мессенджеры (текстовые сообщения).


**Выбираем UDP, если важна скорость (Real-time):**

- **Онлайн-игры:** (CS:GO, Dota). Если потеряется пакет с координатами пули за прошлую миллисекунду, это не страшно, важнее получить новые координаты _быстро_. Ждать переотправки старого пакета в TCP вызвало бы "лаги".
    
- **Потоковое видео/аудио:** (YouTube, Twitch, Skype). Если выпадет пара кадров, картинка просто моргнет. Это лучше, чем если видео остановится для буферизации.
    
- DNS-запросы.
