## 1. Абстрактные классы

### Что такое абстрактный класс

**Абстрактный класс** — это класс, который:

- может содержать **абстрактные методы** (без реализации)
    
- **не может иметь экземпляров**
    
- используется как **базовая заготовка** для других классов


Объявляется с помощью ключевого слова `abstract`.

```java
abstract class Animal {
}
```

---

### Абстрактный метод

**Абстрактный метод**:

- объявляется без тела
    
- содержит только сигнатуру
    
- обязан быть реализован в дочерних классах


```java
abstract void sound();
```

📌 Если в классе есть **хотя бы один абстрактный метод**,  
➡️ **весь класс обязан быть абстрактным**.

---

### Основные правила абстрактных классов

- нельзя создать объект абстрактного класса

```java
Animal a = new Animal(); // ошибка компиляции
```

- абстрактный класс **может содержать**:
    
    - обычные методы
        
    - поля
        
    - конструкторы
    
- если класс наследуется от абстрактного класса, он:
    
    - либо реализует **все** абстрактные методы
        
    - либо сам объявляется `abstract`
    

---

## 2. Почему классы называют «абстрактными»

### Связь с принципом абстракции

**Абстракция** — это принцип ООП:

> выделять главное и отбрасывать второстепенное

Абстрактный класс:

- описывает **общее состояние и поведение**
    
- является **очень приблизительной моделью**
    
- не предназначен для прямого использования


📌 Это «заготовка» для будущих классов.

---

## 3. Реализация абстрактных методов

### Обязательная реализация

Если класс наследуется от абстрактного класса:

```java
abstract class Animal {
    abstract void sound();
}
```

```java
class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Гав");
    }
}
```

---

### Если не реализовать метод

Если **хотя бы один абстрактный метод не реализован**, то:

- класс **обязан** быть объявлен `abstract`
    
- иначе программа **не скомпилируется**


---

### Важные нюансы реализации

При реализации абстрактных методов допускается:

1. **Расширение видимости**

```java
protected → public
```

2. **Сужение типа возвращаемого значения**  (covariant return types)


❌ Нельзя:

- сужать модификатор доступа
    
- менять сигнатуру метода


---

## 4. Почему в Java нет множественного наследования классов

### Проблема ромба (diamond problem)

Если бы Java разрешала наследование от нескольких классов:

- два родителя могли бы иметь **одинаковый метод**
    
- компилятор не знал бы, **какую реализацию выбрать**


```java
class A { void test() {} }
class B { void test() {} }
// class C extends A, B — проблема
```

➡️ Чтобы избежать неоднозначности, в Java:

- **нет множественного наследования классов**
    
- но есть **интерфейсы** (решают проблему иначе)


---

## 5. Перегрузка методов (Overloading)

### Что такое перегрузка

**Перегрузка методов** — это:

> наличие нескольких методов с одинаковым именем,  
> но **разными параметрами**

---

### Сигнатура метода

**Сигнатура метода** =  
👉 имя метода + типы параметров

📌 Имена параметров **не учитываются**  
(они исчезают при компиляции).

---

### Пример перегрузки

```java
void sum(int a, int b) {}
void sum(double a, double b) {}
void sum(int a, int b, int c) {}
```

✔️ Это перегрузка  
❌ Это **не** переопределение

---

### Что нельзя использовать для перегрузки

❌ Нельзя перегружать метод только:

- по возвращаемому типу
    
- по именам параметров


```java
int sum(int a, int b) {}
double sum(int a, int b) {} // ошибка
```

---

### Как выбирается перегруженный метод

- выбор происходит **на этапе компиляции**
    
- типы аргументов могут **расширяться**, но не сужаться


📌 Перегрузка — это **compile-time polymorphism**.

---

## 6. Переопределение методов (Override)

### Что такое переопределение

**Переопределение метода** — это:

> предоставление дочерним классом своей реализации метода родителя

Используется для реализации **полиморфизма**.

---

### Пример переопределения

```java
class Animal {
    void sound() {
        System.out.println("Звук");
    }
}
```

```java
class Cat extends Animal {
    @Override
    void sound() {
        System.out.println("Мяу");
    }
}
```

---

### Ограничения переопределения

У переопределённого метода должно быть:

- ✔️ то же имя
    
- ✔️ те же параметры
    
- ✔️ тот же тип возвращаемого значения
    
- ✔️ **не более узкий** модификатор доступа


❌ Нельзя:

- переопределять `static` методы
    
- переопределять `final` методы
    
- менять сигнатуру


---

### Зачем нужен @Override

Аннотация `@Override`:

- не обязательна
    
- но помогает компилятору проверить, что метод действительно переопределён
    
- защищает от ошибок


---

## 7. Override vs Overload (часто спрашивают)

|Перегрузка|Переопределение|
|---|---|
|Один класс|Родитель + потомок|
|Разные параметры|Те же параметры|
|Compile-time|Runtime|
|Не связан с полиморфизмом|Основа полиморфизма|

---

## 8. Связь уровня 2 с полиморфизмом

- **Перегрузка** — удобство API
    
- **Переопределение** — гибкость поведения
    
- **Абстрактные классы** — основа архитектуры


Позволяют:

- писать код, зависящий от абстракций
    
- легко добавлять новые реализации
    
- поддерживать слабую связанность
