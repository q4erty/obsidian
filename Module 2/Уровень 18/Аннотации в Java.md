## 1. Императивный vs Декларативный подход

Программирование можно разделить на два стиля:

- **Императивный:** Мы описываем **КАК** нужно сделать задачу (пошаговый алгоритм).
    
    - _Пример:_ `for (int i = 0; i < list.size(); i++) { ... }`
    
- **Декларативный:** Мы описываем **ЧТО** мы хотим получить, а детали реализации скрыты.
    
    - _Пример:_ Аннотации. Мы просто помечаем метод `@Override`, говоря компилятору: "Проверь, что я переопределяю метод родителя", но не пишем код проверки сами .
    

---

## 2. Что такое Аннотации?

Аннотации — это специальные метки (метаданные), которые добавляют информацию о коде, но сами по себе не меняют логику выполнения программы напрямую. Эту информацию могут использовать:

1. **Компилятор** (например, для генерации ошибок или предупреждений).
    
2. **Среда разработки** (IDE).
    
3. **Время выполнения** (Runtime) через Reflection API.


### Стандартные аннотации (из java.lang):

- **`@Override`**: Указывает, что метод переопределяет метод суперкласса. Если ошибиться в сигнатуре, компилятор выдаст ошибку.
    
- **`@Deprecated`**: Помечает метод или класс как устаревший. Использовать его не рекомендуется, но можно.
    
- **`@SuppressWarnings`**: Подавляет предупреждения компилятора (например, "unchecked cast").
    
- **`@FunctionalInterface`**: Проверяет, что интерфейс подходит для использования с лямбда-выражениями (имеет ровно один абстрактный метод) .

## 3. Создание своей аннотации

Чтобы создать аннотацию, используется ключевое слово **`@interface`**.

``` java
public @interface MyAnnotation {
    String name();      // Параметр
    int value() default 10; // Параметр со значением по умолчанию
}
```

### Параметры аннотации

В аннотации можно хранить только константы. Допустимые типы:

- Примитивы (`int`, `double`, `boolean`...).
    
- `String`.
    
- `Class` (например, `String.class`).
    
- `Enum`.
    
- Другие Аннотации.
    
- Массивы вышеперечисленных типов (`String[]`, `int[]`) .


**Важное правило `value()`:**

Если в аннотации есть параметр с именем `value`, то при её использовании имя можно опустить:

`@MyAnno(100)` вместо `@MyAnno(value = 100)`.

## 4. Мета-аннотации (Настройка аннотаций)

Это аннотации, которые вешаются над _вашей_ аннотацией, чтобы настроить её поведение.

### `@Target` (Где можно применять?)

Ограничивает места, где аннотация может быть использована (класс `ElementType`):

- `TYPE`: Класс, интерфейс, enum.
    
- `FIELD`: Поле класса.
    
- `METHOD`: Метод.
    
- `PARAMETER`: Аргумент метода.
    
- `CONSTRUCTOR`: Конструктор.
    
- `LOCAL_VARIABLE`: Локальная переменная .


### `@Retention` (Время жизни)

Определяет, до какого момента аннотация сохраняется (класс `RetentionPolicy`):

1. **`SOURCE`**: Видна только в исходном коде. Компилятор её отбрасывает (пример: `@Override`, Lombok).
    
2. **`CLASS`**: Сохраняется в .class файле, но недоступна во время выполнения (Runtime). Это поведение по умолчанию.
    
3. **`RUNTIME`**: Сохраняется в .class файле и доступна во время выполнения через рефлексию (используется чаще всего для своих фреймворков) .


---

## 5. Обработка аннотаций (Runtime)

Чтобы аннотация заработала, кто-то должен её прочитать и выполнить логику. Если Retention = RUNTIME, это делается через **Reflection API**.

**Основные методы:**

- `element.isAnnotationPresent(MyAnno.class)`: Проверяет, есть ли аннотация над элементом (классом/методом/полем).
    
- `element.getAnnotation(MyAnno.class)`: Возвращает сам объект аннотации, чтобы можно было прочитать значения её параметров .


**Пример логики:**

"Если над полем стоит аннотация `@JsonField(name="id")`, то при сериализации в JSON используй имя "id", а не имя переменной java".

## 6. Библиотека Lombok

**Lombok** — это популярная библиотека-плагин, которая использует аннотации с `RetentionPolicy.SOURCE`. Она встраивается в процесс компиляции и **генерирует код** (геттеры, сеттеры, конструкторы) автоматически, избавляя программиста от рутины (boilerplate code).

### Популярные аннотации Lombok:

- **`@ToString`**: Генерирует метод `toString()`, выводящий все поля класса.
    
- **`@EqualsAndHashCode`**: Генерирует корректные методы `equals` и `hashCode`.
    
- **`@Getter` / `@Setter`**: Генерирует геттеры и сеттеры для полей.
    
- **`@NonNull`**: Генерирует проверку на `null` внутри конструктора или метода (выбросит `NullPointerException` с понятным сообщением).
    
- **`@Data`** (не указана в слайдах явно, но подразумевается): Объединяет `@ToString`, `@EqualsAndHashCode`, `@Getter`, `@Setter` и `@RequiredArgsConstructor` в одну мощную аннотацию.
