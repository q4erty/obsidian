## 1. Условные функции в SQL

Условные функции работают по принципу `if-else`, но прямо внутри SQL-запроса. Они позволяют изменять выводимые данные «на лету» в зависимости от заданных условий.

В MySQL встроено несколько базовых условных функций:

- **IF(condition, a, b):** Работает как тернарный оператор в программировании. Если условие выполняется, возвращает значение `a`, иначе — `b`.
    
    - _Пример:_ `IF(length > 120, 'Длинный', 'Короткий')`.
        
- **IFNULL(a, b):** Очень полезная функция для обработки отсутствующих данных. Если значение `a` является `NULL`, функция вернет `b`, в противном случае вернет `a`.
    
    - _Пример:_ `IFNULL(original_language_id, 1)`.
        
- **NULLIF(a, b):** Делает обратное действие — возвращает `NULL`, если значения `a` и `b` совпадают.
    
    - _Пример:_ `NULLIF(return_date, rental_date)`.
        

### Оператор CASE

`CASE` — это самая мощная условная функция, позволяющая создавать разветвленную логику (подобно `if-elif-else` в коде). У неё есть две формы:

1. **Простая форма:** Сравнивает одно выражение с несколькими возможными фиксированными значениями.
    
    - _Синтаксис:_ `CASE column WHEN value1 THEN result1 WHEN value2 THEN result2 ELSE default_result END`.
        
2. **Поисковая форма:** Позволяет задавать уникальные, сложные логические условия (например, диапазоны) для каждой ветки.
    
    - _Синтаксис:_ `CASE WHEN length < 60 THEN 'Короткий' WHEN length > 120 THEN 'Длинный' END`.

## 2. Агрегатные функции

Агрегатные функции выполняют математические вычисления над целым набором значений (группой строк) и возвращают одно итоговое значение.

Основные агрегатные функции:

- **COUNT(*):** Считает количество строк в группе. Если используется без группировки, вернет общее количество строк в таблице.
    
- **SUM(column):** Подсчитывает общую сумму значений в указанной колонке.
    
- **AVG(column):** Вычисляет среднее арифметическое значение в колонке.
    
- **MIN(column):** Находит минимальное значение в колонке.
    
- **MAX(column):** Находит максимальное значение в колонке.

## 3. Группировка данных (GROUP BY)

Оператор `GROUP BY` используется для объединения (группировки) данных по какому-либо общему признаку. В структуре запроса он пишется после блока `WHERE` (если он есть) и перед блоком `ORDER BY`. Очень часто `GROUP BY` работает в паре с агрегатными функциями, например, с `COUNT(*)`, чтобы посчитать количество записей, попавших в каждую группу.

**Строгое правило колонок при группировке:**

Если в запросе используется `GROUP BY`, то в блоке `SELECT` разрешено указывать **только**:

1. Те колонки, по которым непосредственно происходит группировка (перечисленные в `GROUP BY`).
    
2. Колонки, обернутые в агрегатные функции (например, `COUNT(*)`, `SUM(column)`).
    

Если добавить в `SELECT` обычную колонку, которая не является ключом группировки и не обернута в агрегатную функцию, MySQL выберет случайное значение из группы. Вы не сможете контролировать, какая именно строка будет выведена, что приведет к логической ошибке (в строгих режимах SQL это вызовет `Error Code`).

### Группировка по нескольким колонкам

Данные можно группировать сразу по нескольким признакам. Технически количество колонок в `GROUP BY` не ограничено, но на практике обычно используют 2-3 колонки для получения осмысленных результатов (например, сначала сгруппировать по рейтингу, а внутри рейтинга — по языку).

### Продвинутая группировка

В MySQL есть дополнительные инструменты для работы с группами:

- **WITH ROLLUP:** Добавляет в итоговый результат дополнительные строки, содержащие промежуточные итоги (subtotals) по каждой группе и один общий итог (grand total).
    
- **HAVING:** Используется для фильтрации результатов группировки. Работает аналогично `WHERE`, но `WHERE` фильтрует отдельные строки _до_ группировки, а `HAVING` фильтрует уже _сформированные группы_ (например, можно оставить только те группы, где `COUNT(*) > 150`).

## 4. Порядок выполнения SQL-запроса

Важно понимать, что порядок, в котором вы пишете SQL-запрос (синтаксический), отличается от того, в каком порядке сервер базы данных его логически обрабатывает.

**Логический порядок обработки запроса СУБД:**

1. **FROM (и JOIN):** Первым делом сервер определяет, откуда брать данные и как соединять таблицы.
    
2. **WHERE:** Затем происходит фильтрация сырых строк по условиям (это делается строго до группировки).
    
3. **GROUP BY:** Отфильтрованные строки объединяются в группы.
    
4. **HAVING:** Происходит фильтрация уже сформированных групп.
    
5. **SELECT:** Только на этом этапе сервер выбирает те колонки, которые вы указали для вывода.
    
6. **DISTINCT:** Удаляются дубликаты строк (если оператор присутствует).
    
7. **ORDER BY:** Готовый результат сортируется.
    
8. **LIMIT / OFFSET:** В самом конце отсекается нужное количество строк для финального вывода.
    

_Примечание:_ Реальный физический порядок выполнения может слегка отличаться, так как внутренний оптимизатор запросов СУБД (Query Optimizer) может перестраивать план выполнения для скорости, однако итоговый результат всегда будет математически идентичен описанному логическому порядку.
