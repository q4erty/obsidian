## 1. Классификация типов данных

Все типы данных в Java при маппинге можно разделить на три основные группы:

- Простые типы, которые легко сохранить в БД напрямую.
    
- Сложные типы, для которых необходимо писать специальный конвертор.
    
- Очень сложные типы, требующие хранения в отдельной связанной таблице.
    

Hibernate автоматически умеет сохранять множество простых типов:

- Примитивные типы (boolean, int, double) и их классы-обертки (Boolean, Integer).
    
- Строки (`String`).
    
- Продвинутые числа (`BigInteger`, `BigDecimal`).
    
- Даты и время из `java.util`, `java.time` и `java.sql`.
    
- Массивы байтов (`byte[]`) или символов (`char[]`).
    
- Перечисления (Enums).
    
- Любые объекты, реализующие `java.io.Serializable`.
    

(Дополнение: Если Hibernate не может сам определить тип или вы хотите его переопределить — например, сохранить `Integer` в колонку `VARCHAR`, — можно использовать аннотацию `@Type(type="имя-типа")`.)

## 2. Специфический маппинг: Enums и Boolean

### Перечисления (Enum)

Объекты `enum` могут храниться в базе данных двумя способами:

- В виде числа (порядкового номера константы). Для этого используется аннотация `@Enumerated(EnumType.ORDINAL)`.
    
- В виде строки (названия константы). Для этого используется `@Enumerated(EnumType.STRING)`.
    

### Boolean

В SQL исторически нет единого стандарта для типа `Boolean`. Разные базы могут хранить логические значения как:

- `1` или `0`.
    
- `'T'` или `'F'` (True/False).
    
- `'Y'` или `'N'` (Yes/No).
    

При проектировании базы с нуля рекомендуется использовать тип `BIT`. Для явного маппинга можно комбинировать `@Column(columnDefinition = "BIT")` и `@Type(type = "org.hibernate.type.NumericBooleanType")`.

## 3. Вычисляемые и игнорируемые поля

Иногда структура класса не совпадает со структурой таблицы.

- **Игнорируемые поля:** Если в классе есть поле, которое не нужно сохранять в БД, оно помечается аннотацией `@Transient`.
    
- **Вычисляемые поля:** Поля, значения которых генерируются "на лету" с помощью SQL-выражения (например, `width * height`), помечаются аннотацией `@Formula`.
    

## 4. Встраиваемые объекты (Embedded)

Аннотация `@Embedded` позволяет объединить поля дочернего объекта с колонками главной таблицы сущности.

- Вспомогательный класс (например, `UserAddress`) помечается как `@Embeddable`.
    
- Поле этого типа в главной сущности помечается как `@Embedded`.
    
- (Дополнение: Если нужно добавить два таких объекта в один класс, возникнет конфликт имен колонок. Для решения этой проблемы применяется переопределение через аннотацию `@AttributeOverrides`.)
    

## 5. Первичные ключи (Primary Keys)

Каждая сущность должна иметь уникальный идентификатор, помеченный аннотацией `@Id`. Для автоматической генерации ключа добавляется `@GeneratedValue`. Доступны 4 стратегии генерации:

- `AUTO` _(Дополнение: Hibernate сам выбирает стратегию в зависимости от базы данных)._
    
- `IDENTITY` _(Дополнение: Использование автоинкрементного столбца на стороне БД)._
    
- `SEQUENCE` _(Дополнение: Использование последовательностей, характерно для PostgreSQL и Oracle)._
    
- `TABLE` _(Дополнение: Хранение счетчиков в отдельной таблице)._
    

## 6. Маппинг Даты и Времени

В современных БД есть 4 основных типа времени: `DATE`, `TIME`, `TIMESTAMP` и `TIMESTAMP WITH TIME ZONE`.

- **Старый подход (`java.util.Date`):** Регулировался аннотацией `@Temporal`, где указывался нужный формат (`TemporalType.DATE`, `TIME` или `TIMESTAMP`).
    
- **Новый подход (Java 8 `java.time`):** Объекты мапятся напрямую.
    
    - `DATE` -> `LocalDate`.
        
    - `TIME` -> `LocalTime` или `OffsetTime`.
        
    - `TIMESTAMP` -> `Instant`, `LocalDateTime`, `OffsetDateTime` или `ZonedDateTime`.
        
- **Тайм-зоны:** Аннотация `@TimeZoneStorage` позволяет сохранять временную зону даты в отдельную колонку таблицы.
    

## 7. Аудит: Управление обновлением данных

Почти в каждую таблицу принято добавлять колонки `created_time` и `updated_time` для отслеживания времени создания и изменения записи. Hibernate автоматизирует это через аннотации:

- `@CreationTimestamp` — заполняется при добавлении в базу.
    
- `@UpdateTimestamp` — обновляется при каждом изменении.
    

### Перехват событий (Lifecycle Callbacks)

Для реализации сложной логики при изменении объектов используются 7 специальных аннотаций, вешаемых на методы:

- Перед сохранением: `@PrePersist`.
    
- После сохранения: `@PostPersist`.
    
- Перед обновлением: `@PreUpdate`.
    
- После обновления: `@PostUpdate`.
    
- Перед удалением: `@PreRemove`.
    
- После удаления: `@PostRemove`.
    
- После загрузки из базы: `@PostLoad`. Логику этих методов также можно вынести в отдельные классы с помощью `EntityListeners`.
    

## 8. Хранение файлов, JSON и написание конвертеров

- **Файлы:** Большие файлы (например, видео) лучше сохранять на диск сервера, а в БД держать только пути к ним (`c:\db-files\avatar.jpg`). Небольшие изображения можно сохранять прямо в БД с использованием типов `BLOB` (для бинарников) и `CLOB` (для текста).
    
- **JSON/XML:** Hibernate может сериализовать Java-структуры (например, `Map<String, String>`) в единый JSON или XML объект для базы данных с помощью `@JdbcTypeCode(SqlTypes.JSON)`.
    
- **Кастомные конвертеры:** Если нужно сохранить нестандартный формат (например, дату вида `98.12.15`), пишется класс, реализующий интерфейс `AttributeConverter<EntityType, DbType>`.
    
- **Собственные типы Hibernate:** Если нужен глубокий контроль над преобразованием (например, сохранять `LocalTime` как `VARCHAR`), можно создать собственный тип, содержащий методы `wrap()` и `unwrap()`. Затем этот тип регистрируется в конфигурации Hibernate через `MetadataBuilder` или XML.
