## 1. Концепция ORM (Object-Relational Mapping)

**ORM** — это технология программирования, которая связывает базы данных с концепциями объектно-ориентированных языков программирования, создавая «виртуальную объектную базу данных».

### Основные идеи:

- **Соответствие**: Каждой таблице в БД соответствует определенный класс в Java.
    
- **Автономия**: В приложении мы работаем с обычными Java-объектами, которые сами «умеют» сохранять себя в базу и загружаться из нее.
    
- **История подходов**:
    
    1. Объект сам сохраняет себя и обновляет поля из БД.
        
    2. Объект умеет сохранять себя, но делает это только по внешней команде.
        
    3. Объект — это просто данные (POJO), а за его сохранение и загрузку отвечает сторонний сервис. Этот подход стал доминирующим с появлением Hibernate.
        

## 2. Hibernate и появление JPA

**Hibernate** появился в 2001 году как простая альтернатива сложным Enterprise Java Beans (EJB).

- **Ранние версии**: Использовали громоздкие XML-файлы для описания связей между полями класса и колонками таблиц.
    
- **Прорыв в Java 5**: Появление **аннотаций** позволило описывать маппинг прямо в коде класса, а механизм **Proxy** (прокси-заглушек) позволил Hibernate эффективно управлять загрузкой данных.
    

**JPA (Java Persistence API)** — это официальная спецификация Java (стандарт), описывающая, как должны работать ORM-системы.

- Hibernate сегодня полностью реализует стандарт JPA.
    
- В Hibernate есть два набора функций: стандартные (JPA) и собственные (Hibernate Native API).

## 3. Маппинг классов с помощью аннотаций

Чтобы превратить обычный класс в **Entity** (сущность, хранимую в БД), используются следующие аннотации:

### Основные аннотации:

- **`@Entity`**: Помечает класс как сущность БД.
    
- **`@Table`**: Указывает имя таблицы (`name`) и схему (`schema`). Если имена класса и таблицы совпадают, её можно не писать.
    
- **`@Id`**: Помечает поле как первичный ключ (Primary Key).
    
- **`@GeneratedValue`**: Указывает Hibernate автоматически генерировать значения ID при вставке.
    

### Аннотация `@Column`:

Используется для тонкой настройки маппинга полей. Популярные параметры:

- **`name`**: Имя колонки в таблице.
    
- **`unique = true`**: Значения в колонке должны быть уникальными.
    
- **`nullable = false`**: Колонка не может содержать NULL.
    
- **`length`**: Максимальная длина для строковых полей.

## 4. Конфигурирование Hibernate

Для работы Hibernate нужно знать, к какой базе подключаться и какие классы мапить. Настроить это можно через:

1. Файл `hibernate.properties`.
    
2. XML-файл `hibernate.cfg.xml` (самый популярный способ).
    
3. Программную настройку через объект `Configuration`.
    

### Ключевые настройки (Properties):

- **Данные доступа**: URL базы, username, password и JDBC-драйвер.
    
- **SQL Dialect**: Указывает версию SQL конкретной СУБД (например, `PostgreSQLDialect` или `MySQLDialect`), чтобы Hibernate генерировал правильные запросы.
    
- **`hibernate.show_sql`**: Выводит все выполняемые SQL-запросы в консоль (удобно для отладки).
    
- **`hbm2ddl.auto`**: Управляет автоматическим изменением структуры БД при запуске приложения.
    

### Режимы `hbm2ddl.auto`:

- **`validate`**: Только проверяет соответствие классов и таблиц.
    
- **`update`**: Обновляет таблицы (добавляет новые колонки), если нужно.
    
- **`create`**: Удаляет старые таблицы и создает новые при каждом запуске.
    
- **`create-drop`**: Создает таблицы при старте и удаляет их при выключении приложения.
    
- **`none`**: Ничего не делает.

## 5. Основные операции (CRUD)

Вся работа происходит через объект **`Session`**, который получается из **`SessionFactory`**.

1. **Получение (Read)**: `session.get(User.class, id)` — возвращает объект по его ID. Для чтения транзакция обычно не требуется.
    
2. **Сохранение (Create)**: `session.persist(obj)` — стандарт JPA для добавления нового объекта. Также существует старый метод `session.save()`.
    
3. **Удаление (Delete)**: `session.remove(obj)` — удаляет объект из базы.
    

**Важно**: Любые изменения данных (сохранение, удаление, обновление) должны выполняться **внутри транзакции**. Транзакция гарантирует целостность: либо все действия выполнятся успешно, либо всё откатится назад.

---

## Краткий итог:

Вместо того чтобы писать `INSERT INTO users...` и вручную заполнять каждое поле через JDBC, в Hibernate мы просто помечаем класс аннотацией `@Entity` и вызываем `session.persist(user)`. Hibernate сам сгенерирует нужный SQL-запрос, учитывая диалект вашей базы данных.
