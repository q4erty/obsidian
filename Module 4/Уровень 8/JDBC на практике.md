## 1. Транзакции при работе с базой данных

Одной из самых важных концепций при работе с базами данных является **транзакция**. Практически каждая современная СУБД умеет работать с транзакциями, и, соответственно, в JDBC тоже есть их полная поддержка.

**Транзакция** — это группа действий, которые должны быть выполнены только все вместе. Главное правило транзакции: если какое-либо действие из группы не выполнилось или выполнилось с ошибкой, то все остальные действия этой группы должны быть отменены.

_Дополнение: В теории баз данных это свойство называется **Атомарность** (Atomicity) — часть акронима ACID, который описывает требования к надежной транзакционной системе._

### Жизненный цикл и состояния транзакции

У транзакции обычно выделяют три ключевых состояния:

1. **Initial state (Начальное состояние):** Состояние системы перед выполнением группы действий.
    
2. **Success state (Успешное состояние):** Состояние после успешного выполнения всей группы действий транзакции.
    
3. **Failed state (Состояние сбоя):** Состояние, возникающее, если в процессе выполнения произошла ошибка.
    

### Управление транзакциями (SQL команды)

На уровне самой базы данных транзакциями управляют с помощью трех основных команд:

- `begin` (или `start`) — команда, которая выполняется перед началом логической группы действий, открывая транзакцию.
    
- `commit` — команда, фиксирующая изменения. Она вызывается, когда все действия выполнены успешно.
    
- `rollback` — команда отката. Она запускает процесс возврата системы из состояния сбоя (failed state) обратно в начальное состояние (initial state), отменяя все промежуточные изменения.
    

### Управление транзакциями в JDBC

В JDBC за управление транзакциями отвечает объект `Connection`. У него есть специальный параметр — **AutoCommit**.

- По умолчанию этот параметр выставлен в `true`. Это означает, что каждый вызов метода `execute()` (или `executeUpdate()`, `executeQuery()`) объекта `Statement` автоматически оборачивается в свою собственную, отдельную транзакцию.
    
- Если вы хотите выполнить **несколько команд в одной транзакции** (например, списать деньги с одного счета и зачислить на другой), вам нужно:
    
    1. Отключить автоматическую фиксацию: `connection.setAutoCommit(false);`
        
    2. Вызвать все необходимые методы `execute...()` для выполнения запросов.
        
    3. Явно вызвать метод фиксации `connection.commit()` в случае успеха, или метод отката `connection.rollback()` в блоке `catch`, если произошла ошибка.

## 2. Точки сохранения (Savepoints)

С появлением спецификации JDBC 3.0 появилась возможность более гибко и эффективно работать с откатом транзакции. Иногда при ошибке не нужно отменять всю огромную транзакцию целиком, достаточно откатиться до определенного промежуточного этапа.

Для этого используются точки сохранения (Savepoints). Теперь можно устанавливать точки сохранения внутри транзакции.

**Пример использования из кода:**

Java

```
// Создаем точку сохранения в текущей транзакции
Savepoint save = connection.setSavepoint(); [cite: 75]

// Откатываем изменения не к самому началу транзакции, а к созданной точке
connection.rollback(save); [cite: 76]
```

## 3. Виды Statements и PreparedStatement

В спецификации JDBC существуют разные виды statements (объектов для выполнения запросов). Самый базовый — это `Statement`, который мы рассматривали ранее. Однако на практике чаще всего используется его наследник — **`PreparedStatement`**.

_Дополнение: Обычный `Statement` уязвим для SQL-инъекций (когда злоумышленник вводит вредоносный SQL-код в поля формы) и работает медленнее при многократном выполнении однотипных запросов, так как БД каждый раз заново компилирует запрос._

`PreparedStatement` решает эти проблемы. При его использовании мы пишем SQL-запрос, в котором места для подстановки параметров обозначаются знаком вопроса `?`.

**Пример создания и выполнения `PreparedStatement`:**

Java

```
// 1. Запрос с указанием мест для параметров в виде знака "?" 
String sql = "INSERT INTO JC_CONTACT (FIRST_NAME, LAST_NAME, PHONE, EMAIL) VALUES (?, ?, ?, ?)"; [cite: 82]

// 2. Создание запроса. Переменная con — это объект типа Connection [cite: 83]
PreparedStatement stmt = con.prepareStatement(sql); [cite: 83]

// 3. Установка параметров (нумерация начинается с 1) [cite: 84]
stmt.setString(1, firstName); [cite: 84]
stmt.setString(2, lastName); [cite: 84]
stmt.setString(3, phone); [cite: 84]
stmt.setString(4, email); [cite: 84]

// 4. Выполнение запроса (обратите внимание, что сам SQL уже передан при создании) [cite: 85]
stmt.executeUpdate(); [cite: 86]
```

## 4. Работа с RowSet (Краткий обзор)

В презентации также упоминается "Работа с RowSet".

_Дополнение (теоретическая справка, так как подробностей в слайдах нет):_

`RowSet` — это интерфейс, который расширяет классический `ResultSet`. Его главное отличие и преимущество заключается в том, что `RowSet` может работать в "отсоединенном" (disconnected) режиме.

Обычный `ResultSet` требует постоянного активного соединения (`Connection`) с базой данных, пока вы читаете из него данные. `RowSet` может получить данные, закрыть соединение с базой, передать эти данные в другой слой приложения (или даже по сети), там модифицироваться, а затем переподключиться к БД и синхронизировать изменения.

## 3. Дополнение: CallableStatement (Хранимые процедуры)

**CallableStatement** — это специальный интерфейс, предназначенный для вызова **хранимых процедур и функций**, которые уже написаны и сохранены на стороне базы данных.

### Почему это важно:

- **Производительность**: Логика выполняется внутри БД, не перекачивая лишние данные в Java.
    
- **Безопасность**: Доступ дается только к процедуре, а не к таблицам напрямую.
    

### Параметры в CallableStatement:

1. **IN**: Входные параметры (как в PreparedStatement).
    
2. **OUT**: Параметры, которые процедура возвращает обратно в Java. Их нужно регистрировать через `registerOutParameter`.
    
3. **INOUT**: Параметры, которые передаются в процедуру и возвращаются измененными.
    

**Пример использования:**


``` java
// Вызываем процедуру "get_user_count", которая принимает ID отдела и возвращает число сотрудников
String sql = "{call get_user_count(?, ?)}"; 
try (CallableStatement cstmt = connection.prepareCall(sql)) {
    // 1. Устанавливаем входной параметр (ID отдела)
    cstmt.setInt(1, 10); 
    
    // 2. Регистрируем тип выходного параметра (Количество)
    cstmt.registerOutParameter(2, java.sql.Types.INTEGER);
    
    // 3. Выполняем
    cstmt.execute();
    
    // 4. Получаем результат из OUT-параметра
    int count = cstmt.getInt(2);
    System.out.println("Сотрудников в отделе: " + count);
}
```
