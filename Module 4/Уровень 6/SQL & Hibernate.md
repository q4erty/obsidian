### 1. Группы команд SQL

Все операции в SQL-сервере выполняются через запросы, которые делятся на четыре официальные группы:

- **DDL (Data Definition Language)**: Операторы определения данных. Используются для создания (`CREATE`), изменения (`ALTER`) и удаления (`DROP`) объектов базы данных (таблиц, схем).
    
- **DML (Data Manipulation Language)**: Операторы манипуляции данными. Сюда входят `SELECT` (выборка), `INSERT` (вставка), `UPDATE` (обновление) и `DELETE` (удаление).
    
- **DCL (Data Control Language)**: Операторы управления доступом. Используются для выдачи (`GRANT`) или отзыва (`REVOKE`, `DENY`) прав доступа.
    
- **TCL (Transaction Control Language)**: Операторы управления транзакциями. Позволяют фиксировать изменения (`COMMIT`), откатывать их (`ROLLBACK`) или создавать точки сохранения (`SAVEPOINT`).

### 2. Работа со схемами и представлениями (View)

#### Управление схемами

Для создания новой схемы используется команда `CREATE SCHEMA имя;`, а для безопасного удаления — `DROP SCHEMA IF EXISTS имя;`. Если в базе данных несколько схем с одинаковыми именами таблиц, рекомендуется либо всегда указывать имя схемы перед таблицей (`test.user`), либо установить схему по умолчанию с помощью команды `USE имя-схемы;`.

#### Представления (VIEW)

**VIEW** — это «виртуальная таблица», которая не хранит данные сама по себе, а подтягивает их из реальных таблиц при каждом обращении.

- **Создание**: `CREATE VIEW имя AS SELECT-запрос;`.
    
- **Преимущества**:
    
    - **Безопасность**: Можно дать доступ к VIEW, скрыв конфиденциальные колонки (например, зарплату) в основной таблице.
        
    - **Денормализация**: Объединение данных из десятков таблиц в одну удобную структуру.
        
    - **Инкапсуляция**: Изменение структуры БД не ломает код программ, работающих через VIEW.
        
    - **Только чтение**: VIEW, созданные через SELECT, защищают данные от случайного изменения.

### 3. Атрибуты колонок и ключи

При создании или изменении таблицы колонкам можно задавать специальные атрибуты для автоматизации и контроля:

- **PRIMARY KEY**: Главный ключ, обеспечивающий уникальность каждой строки. Используется для связи с другими таблицами.
    
- **UNIQUE KEY**: Гарантирует уникальность значений в колонке, но, в отличие от PK, может быть изменен (например, номер паспорта).
    
- **NOT NULL**: Запрещает хранение значений `NULL`.
    
- **AUTO_INCREMENT**: Сервер сам назначает ID новой записи, увеличивая значение последней на 1.
    
- **DEFAULT**: Устанавливает значение по умолчанию, если оно не указано при вставке.

### 4. Изменение данных (DML)

#### Вставка данных (INSERT)

Существует два основных способа добавления данных:

1. **INSERT INTO ... VALUES**: Прямое указание значений для колонок. Можно вставлять сразу несколько строк через запятую.
    
2. **INSERT INTO ... SELECT**: Вставка данных, полученных в результате другого запроса (например, копирование из другой таблицы).
    

#### Обновление (UPDATE)

Оператор `UPDATE` изменяет существующие записи.

- **Важно**: Всегда используйте условие `WHERE`, иначе данные изменятся во всей таблице.
    
- **Сложные сценарии**: Можно обновлять данные в одной таблице, используя значения из другой через `JOIN` (связывание по ID).
    

#### Удаление (DELETE vs TRUNCATE)

- **DELETE FROM**: Удаляет конкретные строки по условию `WHERE`.
    
- **TRUNCATE TABLE**: Команда DDL, которая мгновенно очищает всю таблицу. Это работает быстрее, чем `DELETE`, так как не логирует удаление каждой строки.
    
- **DROP TABLE**: Полностью удаляет и данные, и саму структуру таблицы из базы.

### 5. Изменение структуры (ALTER TABLE)

Для изменения уже существующей таблицы используется оператор `ALTER TABLE` с командами:

- **ADD**: Добавить колонку, индекс или первичный ключ.
    
- **MODIFY / ALTER**: Изменить тип данных или атрибуты колонки (например, увеличить длину `VARCHAR`).
    
- **DROP**: Удалить колонку или ключ.

### 6. Индексы и производительность

**Индекс** — это отсортированный список ID (ссылок), который позволяет SQL-серверу быстро находить нужные строки, не перебирая миллионы записей.

- **Создание**: `ALTER TABLE таблица ADD INDEX имя_индекса (колонка);`.
    
- **Составные индексы**: Создаются по нескольким колонкам одновременно для ускорения сложных фильтров.
    
- **Нюанс**: Индексы ускоряют чтение (`SELECT`), но замедляют запись (`INSERT`, `UPDATE`), так как серверу нужно обновлять сам индекс. Также они занимают место на диске.

### 7. Целостность данных (Constraints)

Для предотвращения появления «мусорных» данных используются ограничения (**Constraints**).

#### FOREIGN KEY (Внешний ключ)

Связывает колонку одной таблицы с первичным ключом другой, гарантируя, что ссылка всегда указывает на существующий объект.

#### Каскадные операции (ON UPDATE / ON DELETE)

Определяют, что делать с зависимыми записями при изменении или удалении родительской строки:

- **CASCADE**: Автоматически изменяет или удаляет зависимые строки.
    
- **SET NULL**: Устанавливает значение в `NULL` для зависимых строк.
    
- **RESTRICT / NO ACTION**: Запрещает удаление родительской строки, пока на нее есть ссылки.

### Дополнение: Связь с Hibernate

Хотя лекция сосредоточена на SQL, в контексте **Hibernate** (упомянутого в названии модуля) эти операции автоматизируются:

- `INSERT` соответствует методу `persist()` или `save()`.
    
- `UPDATE` происходит автоматически при изменении состояния объекта внутри транзакции (dirty checking).
    
- `DELETE` соответствует методу `remove()`.
    
- Атрибуты колонок (вроде `UNIQUE` или `NOT NULL`) задаются через аннотации `@Column(unique = true, nullable = false)`.
    
- Связи `FOREIGN KEY` и каскадные правила настраиваются через параметры `cascade` в аннотациях `@OneToMany` или `@ManyToOne`.
