## 1. Создание собственных исключений

Java позволяет разработчику создавать свои типы ошибок, если стандартных (как `RuntimeException`) недостаточно для описания конкретной проблемы в программе.

- **Как создать:** Нужно создать класс и унаследовать его от `Exception` (для проверяемых) или `RuntimeException` (для непроверяемых).
    
- **Зачем это нужно:** Чтобы вызывающий код мог через блок `catch` специфично отреагировать именно на вашу ошибку, а не на общую «ошибку в программе».
    
- **Пример из лекции:** 

```java
    class MyException extends Exception { }
    
    Вы можете создать объект этого класса и бросить его с помощью `throw myException;`.
```

## 2. Stack Trace (Трассировка стека)

Когда происходит исключение, Java-машина знает не только, что случилось, но и **весь путь**, который прошла программа до этой точки.

- **Что это такое:** Список всех методов, которые были вызваны (в обратном порядке) до момента возникновения ошибки.
    
- **Метод `getStackTrace()`**: Каждый объект-исключение имеет этот метод. Он возвращает массив элементов `StackTraceElement`.
    
- **Что содержит `StackTraceElement`:**
    
    1. Имя класса.
        
    2. Имя метода.
        
    3. Имя файла.
        
    4. Номер строки, где произошел вызов.


> **Пояснение:** Стек работает по принципу стопки тарелок (LIFO). Последний вызванный метод находится наверху стопки. Когда метод завершается, он «снимается» со стопки. Если происходит ошибка, Java «фотографирует» эту стопку, чтобы вы видели цепочку вызовов.

## 3. Проблема закрытия ресурсов (До появления Java 7)

Раньше при работе с внешними ресурсами (файлы, сетевые соединения) программисты сталкивались с проблемой: ресурс **обязательно** нужно закрыть, даже если произошла ошибка.

**Старый громоздкий подход:**

Приходилось открывать ресурс в `try`, а закрывать в `finally`, предварительно проверяя на `null`, что приводило к «лестницам» кода и потенциальным новым ошибкам в самом блоке закрытия.

---

## 4. Оператор try-with-resources

В Java 7 появился элегантный способ автоматического управления ресурсами.

- **Синтаксис:** Ресурсы объявляются в круглых скобках сразу после слова `try`.
    
    Java
    
    ```
    try (FileOutputStream output = new FileOutputStream("file.txt")) {
        // работаем с файлом
    } catch (IOException e) { ... }
    ```
    
- **Главный плюс:** Как только код выходит из блока `try` (нормально или из-за ошибки), Java **автоматически** вызовет метод `close()` для всех объявленных там ресурсов.
    

---

## 5. Интерфейс AutoCloseable

Не любой объект можно засунуть в скобки `try-with-resources`.

- **Условие:** Класс объекта должен реализовывать интерфейс `AutoCloseable`.
    
- **Метод `close()`**: В этом интерфейсе всего один метод — `close()`. Именно его Java ищет и вызывает автоматически.
    
- **Важно:** Большинство стандартных классов Java для работы с потоками ввода-вывода (FileInputStream, Scanner и т.д.) уже реализуют этот интерфейс.


---

## 6. Несколько переменных одновременно

Если вам нужно работать с несколькими файлами (например, копировать из одного в другой), их можно перечислить в `try` через точку с запятой.

**Пример:**

Java

```
try (Scanner scanner = new Scanner(System.in);
     FileOutputStream output = new FileOutputStream("result.txt")) {
    // Код работает с обеими переменными
} 
// Оба ресурса закроются автоматически в конце!
```

### Подводя итоги лекций об исключениях:

1. **Исключения** — это не крах программы, а способ управления ошибками.
    
2. **Stack Trace** — ваш главный инструмент при отладке (дебаге).
    
3. **Try-with-resources** — современный стандарт работы с файлами и сетью, который бережет память и предотвращает утечки ресурсов.
    
4. **Собственные исключения** делают архитектуру вашего приложения понятнее для других разработчиков.
