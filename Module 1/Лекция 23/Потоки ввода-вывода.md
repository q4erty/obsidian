## 1. Что такое «Поток» (Stream)?

Представь, что твоя программа — это **бассейн**.

- Данные (файлы, текст, картинки) — это **вода**.
    
- **Поток (Stream)** — это **труба**, по которой вода течет.


В Java нельзя просто взять и «телепортировать» файл целиком в переменную. Мы должны подключить к файлу «трубу» и перекачать его по байтам (по капелькам).

### Два главных направления:

1. **InputStream (Входящий поток):** Труба, по которой вода вливается **В** твой бассейн (программу).
    
    - _Пример:_ Чтение файла, скачивание картинки из интернета, ввод текста с клавиатуры.
    
2. **OutputStream (Исходящий поток):** Труба, по которой вода выливается **ИЗ** твоего бассейна.
    
    - _Пример:_ Запись в файл, отправка сообщения на сервер.
    

---

## 2. Байт vs Символ (Ключевое различие)

Компьютер понимает только нули и единицы (байты). Человек понимает буквы (символы). В Java для этого есть два набора труб:

| **Что качаем?**          | **Труба для входа (Чтение)** | **Труба для выхода (Запись)** | **Для чего нужно?**                     |
| ------------------------ | ---------------------------- | ----------------------------- | --------------------------------------- |
| **Байты** (сырые данные) | `InputStream`                | `OutputStream`                | Картинки, видео, музыка, архивы.        |
| **Символы** (текст)      | `Reader`                     | `Writer`                      | Текстовые файлы (.txt), сообщения, код. |

> **Запомни:** Если в названии класса есть слово **Stream** — это про байты (картинки/звук). Если **Reader/Writer** — это про текст.

## 3. Принцип «Матрешки» (или Конструктор Lego)

В лекции ты видел страшные конструкции вроде:

Java

```
BufferedReader reader = new BufferedReader(new InputStreamReader(System.in));
```

**Почему так сложно?**

В Java каждая «труба» умеет делать только **одну** простую вещь. Чтобы получить крутой функционал, мы соединяем трубы друг с другом (вкладываем одну в другую).

**Разберем пример выше по слоям (изнутри наружу):**

1. **`System.in`**: Это сырые байты, летящие с клавиатуры. (Труба с сырой водой).
    
2. **`InputStreamReader`**: Это **переходник**. Он берет сырую воду (байты) и превращает её в газировку (символы). Он «учит» байтовый поток понимать буквы.
    
3. **`BufferedReader`**: Это **ведро (буфер)**.
    
    - _Без него:_ Ты бегаешь к крану за каждой каплей (каждым символом). Это медленно.
        
    - _С ним:_ Ты набираешь полное ведро воды за раз, а потом пьешь из ведра. Это быстро.
    

**Итог:** Мы взяли поток с клавиатуры -> превратили в текст -> ускорили чтение буфером.

## 4. Чтение с консоли (Клавиатура)

### Способ 1: Scanner (Для новичков)

Это как «швейцарский нож». Он умеет всё и сразу, прячет внутри себя все эти потоки.

Java

```
Scanner console = new Scanner(System.in);
String s = console.nextLine(); // Дай мне строку
int n = console.nextInt();     // Дай мне число
```

- _Плюс:_ Удобно.
    
- _Минус:_ Немного медленнее работает с огромными объемами данных.
    

### Способ 2: BufferedReader (Для профи)

Тот самый «конструктор», который мы разобрали выше.

Java

```
BufferedReader reader = new BufferedReader(new InputStreamReader(System.in));
String s = reader.readLine(); // Читает только строки!
```

- _Плюс:_ Работает очень быстро.
    
- _Минус:_ Читает только текст. Если нужно число, придется превращать строку в число вручную (`Integer.parseInt(s)`).

## 5. Работа с памятью: ByteArrayInputStream / Output

Иногда нам не нужно писать данные в файл на жесткий диск (это долго). Мы хотим поработать с данными «в уме» (в оперативной памяти).

Представь, что:

- **Файл** — это запись в толстую тетрадь, которая лежит в шкафу (долго доставать).
    
- **Массив байтов (byte array)** — это стикер у тебя на лбу (доступ моментальный).


### ByteArrayInputStream

Позволяет программе «обмануться» и думать, что она читает файл, хотя на самом деле она читает данные просто из массива в памяти.

### ByteArrayOutputStream

Позволяет записывать данные в «динамический массив».

- Обычно массив в Java фиксированной длины. Но этот поток работает как резиновый мешок: ты кидаешь туда байты, а он сам расширяется.
    
- В конце ты говоришь `toByteArray()` — и получаешь готовый массив со всем, что ты туда записал.

## 6. Что такое «Буферизация»? (Важно!)

В лекции упоминается `BufferedInputStream`.

- **Без буфера:** Ты переносишь кучу кирпичей по одному. Взял — отнес, вернулся — взял следующий. (Очень много лишних движений, диск постоянно крутится).
    
- **С буфером:** Ты берешь тачку. Нагрузил полную тачку кирпичей (блок данных), отвез один раз.
    

> **Совет:** Почти всегда, когда работаешь с файлами, используй буферизированные потоки (`Buffered...`). Это стандарт производительности.

---

## Главное резюме (шпаргалка):

1. **Потоки** — это трубы для данных.
    
2. **InputStream/OutputStream** — для картинок и музыки (байты).
    
3. **Reader/Writer** — для текста (символы).
    
4. **Классы-обертки:** В Java мы надеваем одну трубу на другую, чтобы добавить суперсилу (например, скорость через буфер или перевод байтов в текст).
    
5. **Scanner** — удобный, **BufferedReader** — быстрый.
