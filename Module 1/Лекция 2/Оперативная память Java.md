В Java оперативная память (RAM), выделенная под программу, делится на две важные области: **Стек (Stack)** и **Куча (Heap)**.

### 1. Где что лежит?

- **Стек (Stack):** Здесь хранятся локальные переменные (те, что внутри методов). Если ты написал `String name = "Amigo";`, то само имя `name` (та самая «ссылка» или «адрес») лежит в Стике. Это очень быстрая память, но она маленькая.
    
- **Куча (Heap):** Это большая область памяти, где хранятся все **объекты**. Текст `"Amigo"` — это объект. Он лежит в Куче.


### 2. Как это работает на примере?

Представь, что Стек — это твоя записная книжка, а Куча — это огромный склад. В записной книжке (Стек) ты пишешь: _«Посылка с кроссовками лежит на складе, на полке №548»_.

- Запись в блокноте — это **ссылка** (адрес).
    
- Сами кроссовки — это **значение** (объект).


Когда ты обращаешься к переменной, Java смотрит в Стек, берет оттуда адрес, «прыгает» по этому адресу в Кучу и достает оттуда текст.

### 3. Особенность String: String Pool

В Java строки настолько популярны, что для них в Куче (Heap) выделили специальное «VIP-место» — **String Pool (Пул строк)**.

- Когда ты создаешь строку `String s1 = "Java";`, Java сначала смотрит в этот Пул.
    
- Если там уже есть слово "Java", она не будет создавать новую строку, а просто даст тебе ссылку на уже существующую.
    
- Это экономит кучу памяти, если в твоей программе тысячи одинаковых слов.


### Итог:

1. **В переменной (в Стике)** — лежит только «номер полки» (адрес в памяти).
    
2. **В Куче (Heap)** — лежат сами данные (буквы строки).
    
3. **В String Pool** — лежат уникальные значения строк, чтобы не плодить дубликаты.


**Почему это важно знать?** Потому что когда ты пишешь `s1 == s2` для строк, Java сравнивает не буквы, а **адреса** (номера полок в блокноте). Именно поэтому строки правильно сравнивать через метод `.equals()`, который идет по адресу и проверяет каждую букву.
