### 1. Можно ли использовать другие объекты в Map?

**Короткий ответ: Можно и нужно.** В презентации указано, что в качестве ключей и значений могут выступать **любые объекты** — числа, строки или **объекты других классов**.

Однако есть критически важное дополнение, которого нет в слайдах:

- **Для HashMap:** Если ты используешь свой класс (например, `User` или `Car`) в качестве **ключа**, ты **обязан** правильно переопределить методы `equals()` и `hashCode()`. Если этого не сделать, ты не сможешь найти значение в мапе, даже если передашь точно такой же объект, потому что Java будет считать их разными.
    
- **Для ключей:** Лучше всего использовать **immutable** (неизменяемые) объекты. Если ты изменишь поле объекта, которое участвует в расчете `hashCode`, пока он лежит в Map, ты его больше никогда оттуда не достанешь («эффект потерянного элемента»).

### 2. Comparable vs Comparator: подробный разбор

Для `TreeMap` (и `TreeSet`) порядок — это всё. Чтобы дерево понимало, куда положить новый элемент (левее или правее), ему нужно сравнить два объекта: "больше", "меньше" или "равно".

#### **Интерфейс Comparable («Я сам умею себя сравнивать»)**

Этот интерфейс реализуется **внутри** класса, который ты хочешь использовать как ключ. У него есть один метод `compareTo(Object o)`.

- **Логика:** Объект говорит: «Я знаю, как сравнить себя с другим таким же объектом».
    
- **Пример:** Класс `String` или `Integer` уже реализуют `Comparable`. Поэтому `TreeMap<String, String>` работает «из коробки» (сортирует по алфавиту).
    

#### **Интерфейс Comparator («Внешний судья»)**

Используется, если:

1. Класс ключа **не реализует** `Comparable` и ты не можешь его изменить (например, класс из чужой библиотеки).
    
2. Тебе нужна **другая логика** сортировки (например, не по алфавиту, а по длине строки).
    

Ты создаешь отдельный объект-компаратор и передаешь его в конструктор `TreeMap` при создании.

**Пример из презентации (на основе студентов):** В коде лекции создается `TreeMap`, куда передается **анонимный класс** `Comparator`. Он берет двух студентов и сравнивает их суммарный балл по предметам (дизайн + математика + английский).

Java

```
// Пример логики из презентации:
public int compare(Student o1, Student o2) {
    int gradeFirst = o1.desing + o1.english + o1.math; 
    int gradeSecond = o2.desing + o2.english + o2.math; 
    return Integer.compare(gradeFirst, gradeSecond); // Возвращает -1, 0 или 1
}
```

---

### Резюме по сортировке:

- Если в `TreeMap` положить объект, который не является `Comparable` и не дать `Comparator`, программа упадет с ошибкой `ClassCastException` при попытке добавить первый элемент.
    
- **Сравнение:** * `Comparable` — это **естественная** сортировка (одна на весь класс).
    
    - `Comparator` — это **настраиваемая** сортировка (их может быть сколько угодно: по цене, по дате, по рейтингу).
