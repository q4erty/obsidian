## 1. Устройство Java-программы

Каждая программа на Java — это набор взаимодействующих **классов** и **объектов**.

- **Класс** — это «чертеж» или шаблон, который определяет внешний вид объекта и его функции. Программист выступает в роли пректировщика, создавая эти чертежи.
    
- **Объект (Экземпляр)** — это конкретная «деталь», созданная на основе чертежа-класса.
    
- **Поля и методы** — класс объединяет в себе данные (поля) и способы работы с ними (методы).


> **Важное правило проектирования:** Код должен быть прежде всего **понятен людям**. Неправильный, но понятный код можно исправить, а правильный, но запутанный — только выбросить и переписать.

## 2. Жизненный цикл объекта и Конструкторы

Объекты создаются с помощью оператора **new**, который резервирует память и запускает специальный метод — **конструктор**.

Особенности конструктора:

1. Его имя **всегда совпадает** с именем класса.
    
2. У него **нет типа возвращаемого значения** (даже `void`).
    
3. Он предназначен для инициализации объекта (обработки входных параметров).

### Виды конструкторов:

- **Конструктор по умолчанию:** Если вы не написали ни одного конструктора, Java сама добавит пустой публичный конструктор без параметров.
    
- **Пользовательские конструкторы:** Вы можете создать один или несколько конструкторов с разными параметрами.
    
- **Важно:** Если вы добавили хотя бы один свой конструктор, Java **не будет** автоматически создавать конструктор по умолчанию — его придется дописать вручную, если он нужен.

## 3. Порядок инициализации переменных

Когда вы создаете объект (`new MyClass()`), Java выполняет действия в строгом порядке:

1. Выделяется память под объект.
    
2. Переменные класса инициализируются значениями по умолчанию или стартовыми значениями в том порядке, в котором они **объявлены в коде**.
    
3. Выполняется код конструктора.


> **Совет:** Не пишите в конструкторах сложную логику. Она увеличивает риск ошибок, которые сложно обрабатывать на этапе создания объекта.

## 4. Глубокое погружение в ООП (Дополнение)

#### А. Инкапсуляция: Свойства (Getter и Setter)

Лекция 12 уточняет, что в Java принято делать все поля класса **private**.

- Прямой доступ к переменным из других классов запрещен.
    
- Для безопасного взаимодействия используются методы:
    
    - **Getter** — возвращает значение поля.
        
    - **Setter** — устанавливает новое значение, позволяя добавить проверки (например, чтобы цена не была отрицательной).

#### Б. Наследование: Класс Object

Абсолютно все классы в Java неявно наследуются от базового класса **Object**. Благодаря этому любой созданный вами объект сразу «умеет» использовать стандартные методы, такие как `equals()` и `hashCode()`.

## 5. Сравнение объектов: equals() и hashCode()

Сравнение объектов через `==` сравнивает только их адреса в памяти (ссылки). Чтобы сравнивать объекты по их внутреннему содержанию, используются специальные методы.

| **Метод**      | **Описание**                                                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **equals()**   | Проверяет логическое равенство объектов (например, совпадают ли имена у двух «Котов»).                                                 |
| **hashCode()** | Возвращает числовой «отпечаток» объекта (32-битное число `int`). Сравнить два числа гораздо быстрее, чем сравнивать все поля объектов. |

Контракт equals() и hashCode():

- Если два объекта одинаковы (`equals` вернул `true`), их `hashCode` **обязаны быть равны**.
    
- Если `hashCode` разные — объекты **точно разные**.
    
- Если `hashCode` одинаковые — это еще не значит, что объекты равны (могла произойти коллизия), их нужно допроверить через `equals`.
