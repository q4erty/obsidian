## 1. Понятие «Правильная работа программы»

Новички считают, что программа хороша, если она просто выполняет задачу. Опытные разработчики знают: программа должна быть **устойчивой**.

- **Проблема:** В реальном мире всё идет не по плану (нет интернета, файл удален, ввели букву вместо цифры).
    
- **Решение:** Программа должна уметь «отлавливать» такие ситуации и адекватно на них реагировать, а не просто «вылетать» с ошибкой.


## 2. Что такое Исключение (Exception)?

**Исключение** — это событие (объект), которое возникает во время выполнения программы и нарушает её нормальный ход.

- Когда происходит ошибка, Java создает объект исключения, который содержит информацию о том, что случилось и где.


### Механизм обработки: try-catch

Для обработки ошибок используется блок `try-catch`:

1. **`try { ... }`**: сюда помещается код, который _может_ вызвать ошибку.
    
2. **`catch (ТипИсключения имя) { ... }`**: этот блок сработает только в том случае, если внутри `try` возникла ошибка указанного типа.


---

## 3. Выбрасывание исключений (throw)

Вы можете сами создать и «бросить» исключение, если логика вашей программы нарушена (например, возраст пользователя отрицательный).

- **Ключевое слово `throw`**: используется для мгновенной остановки метода и передачи ошибки наверх.
    
- **Пример:** `throw new Exception("Ошибка!");`


---

## 4. Ключевое слово finally

Блок `finally` следует после `catch` и выполняется **всегда**, вне зависимости от того, возникла ошибка или нет.

- **Зачем нужен?** Для «уборки»: закрыть открытый файл, разорвать соединение с базой данных или сетью.
    
- Код в `finally` выполнится, даже если в блоках `try` или `catch` есть оператор `return`.


---

## 5. Иерархия и виды исключений

Все исключения в Java — это объекты, которые наследуются от класса **Throwable**.

### Основные ветви:

1. **Error (Ошибки системы):** Серьезные проблемы в самой Java-машине (например, закончилась память — `OutOfMemoryError`). Программа обычно не должна их обрабатывать, она просто падает.
    
2. **Exception (Исключения):** Ошибки, которые мы можем и должны обрабатывать. Делятся на две группы:
    
    - **Unchecked (Непроверяемые / RuntimeException):** Ошибки логики программиста (например, деление на ноль `ArithmeticException` или обращение к `null` — `NullPointerException`). Компилятор не заставляет вас их обрабатывать.
        
    - **Checked (Проверяемые):** Ошибки, которые не зависят от программиста (например, `IOException` — файл не найден). Компилятор **обязан** видеть, что вы либо обработали их в `try-catch`, либо «пробросили» дальше.


---

## 6. Ключевое слово throws

Если метод может вызвать **checked-исключение**, но вы не хотите обрабатывать его прямо здесь, вы должны предупредить об этом в заголовке метода:

- `public void readFile() throws IOException { ... }`
    
    Это заставляет любого, кто вызывает этот метод, также либо обработать ошибку, либо пробросить её еще выше.


---

## 7. Множественный перехват (Multi-catch)

Часто один блок кода может выбросить несколько разных типов исключений. Чтобы не дублировать код обработки, начиная с Java 7, их можно объединять.

**Как было раньше:**

Java

```
catch (IOException e) { log(e); }
catch (SQLException e) { log(e); }
```

**Как можно сейчас (принцип DRY — Don't Repeat Yourself):**

Java

```
catch (IOException | SQLException e) {
    log(e); // Один код для разных типов ошибок
}
```

---

### Дополнение: Почему это важно?

- **Checked исключения** заставляют вас думать о сбоях заранее. Это «страховка» на этапе написания кода.
    
- **Unchecked исключения** сигнализируют о том, что в коде баг, который нужно исправить (а не просто «замять» блоком catch).


**Главный совет из лекции:** Никогда не оставляйте блок `catch` пустым. Если вы «поймали» ошибку и ничего не сделали, найти причину сбоя в будущем будет практически невозможно.
